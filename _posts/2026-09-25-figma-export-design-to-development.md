Figma에서 화면을 만들고 나면 다음 단계가 있다.

처음에는 단순하게 생각했다.

```text
디자인 완성
↓
이미지로 저장
↓
코드에 넣기
```

그래서 필요한 이미지를 그냥 PNG로 저장하면 된다고 생각했다.

하지만 실제 프로젝트에 적용하려고 하니 선택해야 하는 것이 생각보다 많았다.

```text
PNG?

JPG?

SVG?

몇 배율로 저장하지?

투명 배경은?

아이콘도 PNG로 저장하면 되나?

로고는?

스크린샷은?

웹에서는 WebP가 좋다는데
Figma에서는 어떻게 하지?
```

화면 하나를 Figma에서 보는 것과 실제 웹이나 앱에서 사용할 **Asset**으로 내보내는 것은 조금 다른 문제였다.

Figma Design은 현재 PNG, JPG, SVG, PDF 형식으로 정적 디자인을 Export할 수 있고, Layer·Frame·Component·Group·Section이나 Slice를 이용한 특정 영역도 내보낼 수 있다.

이번 글에서는 Figma에서 만든 디자인을 실제 개발에 가져가기 위해 필요한 Export의 기본을 정리해보려고 한다.

---

## Export란?

Figma의 Export는 말 그대로

```text
Figma 안에서 만든 것
↓
Figma 밖에서 사용할 파일
```

로 내보내는 과정이다.

예를 들어 Figma에서 앱 아이콘을 만들었다면

```text
app-icon.png
```

으로 저장해서 프로젝트에 넣을 수 있다.

로고를 만들었다면

```text
logo.svg
```

로 내보낼 수도 있다.

화면 전체를 공유하려면

```text
home-screen.png
```

처럼 이미지로 저장할 수 있다.

즉 Figma 파일 자체를 넘기는 것이 아니라

**실제 개발이나 문서, 발표 자료 등에서 사용할 수 있는 파일로 만드는 과정**이다.

---

## Figma에서 무엇을 Export할 수 있을까?

처음에는 Frame 전체만 Export할 수 있는 줄 알았다.

실제로는 다양한 단위를 선택해서 내보낼 수 있다.

예를 들면

```text
Frame

Layer

Component

Group

Section
```

등을 선택해서 Export할 수 있다.

필요한 영역만 따로 내보내고 싶다면 Slice를 사용할 수도 있다. 현재 Figma는 개별 Layer부터 Frame, Component, Group, Section, Slice 영역과 현재 페이지 전체까지 다양한 범위의 Export를 지원한다.

예를 들어 하나의 홈 화면 안에

```text
Home Frame
│
├─ Logo
├─ Banner
├─ Cafe Card
└─ Navigation
```

이 있다고 해보자.

전체 화면이 필요하면

```text
Home Frame
```

을 Export하면 되고,

로고만 필요하다면

```text
Logo
```

만 선택해서 Export하면 된다.

---

## 기본적인 Export 방법

기본 흐름은 어렵지 않다.

```text
내보낼 요소 선택
↓
오른쪽 패널의 Export
↓
+ 버튼
↓
형식 선택
↓
설정 확인
↓
Export
```

현재 Figma에서는 선택한 Layer의 오른쪽 패널에서 Export 설정을 추가할 수 있으며, 하나의 요소에 여러 Export 설정을 동시에 지정하는 것도 가능하다. Preview로 결과를 미리 확인할 수도 있다.

예를 들어 같은 로고를

```text
SVG
+
PNG 2x
```

두 가지 형태로 동시에 설정해둘 수도 있다.

이렇게 해두면 필요할 때 각각 다시 설정하지 않아도 된다.

---

## 가장 헷갈렸던 것은 파일 형식이었다

Export 버튼을 누르는 것 자체는 쉽다.

진짜 고민은 그다음이다.

```text
PNG

JPG

SVG

PDF
```

중 무엇을 골라야 할까?

처음에는

```text
PNG가 화질 좋아 보이니까
전부 PNG로 하면 되는 것 아닌가?
```

라고 생각했다.

하지만 형식마다 잘 맞는 용도가 달랐다.

---

## PNG — 투명 배경이 필요한 이미지

PNG는 개발하면서 가장 익숙하게 접한 이미지 형식 중 하나였다.

특히 **투명 배경이 필요한 이미지**를 사용할 때 편하다.

예를 들어

```text
앱 아이콘

일러스트

배경이 없는 이미지

투명 효과가 필요한 그래픽
```

같은 경우다.

예를 들어 로고 주변에 배경이 없어야 한다면

```text
logo.png
```

형식으로 내보낼 수 있다.

PNG는 픽셀 기반의 Raster 이미지다.

그래서 크기를 계속 확대하면 어느 순간 픽셀이 보이기 시작할 수 있다.

```text
작은 PNG
↓
아주 크게 확대
↓
흐려질 수 있음
```

따라서 아이콘이나 단순한 로고처럼 벡터로 유지할 수 있는 요소라면 PNG보다 SVG가 더 적합할 수도 있다.

---

## JPG — 사진처럼 색상이 많은 이미지

JPG는 보통

```text
사진

배경 이미지

색상 변화가 많은 이미지
```

에 잘 맞는다.

투명 배경이 필요하지 않고 사진처럼 픽셀이 복잡한 이미지라면 파일 크기를 줄이기에도 유리하다.

예를 들어 카페 서비스에서

```text
매장 사진

커피 사진

배경용 사진
```

같은 이미지를 내보낸다고 생각할 수 있다.

반대로

```text
아이콘

로고

단순 선 그래픽
```

을 JPG로 저장하는 것은 보통 좋은 선택이 아니다.

압축 과정에서 선이나 글자 주변이 흐릿하게 보일 수 있기 때문이다.

---

## PNG와 JPG를 간단하게 구분하면

초보 단계에서는 이 정도로 생각했다.

```text
투명 배경 필요
또는
그래픽 요소
→ PNG

사진 중심
+ 투명 배경 필요 없음
→ JPG
```

물론 실제 웹 최적화 단계에서는 파일 크기나 WebP 같은 다른 형식도 고려해야 하지만,

Figma Export를 처음 배울 때는 이 기준만 알아도 선택하기 훨씬 쉬웠다.

---

## SVG — 개발하면서 특히 중요했던 형식

개발 프로젝트에서는 **SVG**를 자주 만나게 된다.

처음에는 그냥 또 다른 이미지 확장자라고 생각했다.

하지만 PNG나 JPG와는 성격이 많이 다르다.

SVG는 Vector 기반이다.

즉 픽셀을 저장하는 방식이 아니라

```text
선

좌표

도형

색상
```

등의 정보를 기반으로 이미지를 표현한다.

그래서 크기를 키워도 비교적 선명하게 유지된다.

```text
16 × 16

32 × 32

128 × 128
```

처럼 크기가 달라져도 PNG처럼 특정 해상도에 묶이지 않는다.

---

## SVG는 어디에 잘 어울릴까?

대표적으로

```text
아이콘

로고

단순한 심볼

벡터 일러스트
```

같은 것들이다.

예를 들어

```text
검색 아이콘

설정 아이콘

홈 아이콘

GitHub 아이콘
```

같은 UI 아이콘이라면 SVG가 잘 맞는다.

웹에서도 크기를 CSS로 조절하기 쉽다.

```html
<img src="/icons/search.svg" alt="검색">
```

처럼 사용할 수도 있다.

또 SVG 코드를 직접 다룰 수도 있기 때문에 UI 개발에서는 활용도가 높다.

---

## 아이콘을 PNG로만 만들었을 때 생기는 문제

예를 들어 Figma에서

```text
24 × 24
```

아이콘을 PNG로 Export했다고 해보자.

그런데 나중에 화면에서

```text
48 × 48
```

로 크게 사용하고 싶어졌다.

원래 이미지가 작다면 확대하면서 흐려질 수 있다.

그러면 다시 Figma로 돌아가서 큰 크기로 Export해야 할 수도 있다.

하지만 SVG라면

```text
24px

48px

96px
```

처럼 필요한 크기로 조절해서 사용할 수 있다.

그래서 단순 아이콘이나 로고를 Export할 때는

```text
PNG부터 선택
```

하기보다

```text
SVG로 사용할 수 있는가?
```

를 먼저 확인하는 습관이 좋다고 느꼈다.

---

## SVG는 왜 2x가 없을까?

PNG를 Export하면

```text
1x
2x
3x
```

같은 배율을 볼 수 있다.

그런데 SVG에서는 이런 배율이 크게 의미가 없다.

Vector 형식이기 때문이다.

현재 Figma에서도 SVG Export는 1x만 지원한다. 필요한 표시 크기는 SVG 자체의 코드나 HTML/CSS의 width와 height 등으로 조절할 수 있다.

예를 들어

```html
<img
  src="logo.svg"
  width="120"
  alt="서비스 로고"
/>
```

처럼 개발 단계에서 크기를 지정할 수 있다.

---

## PDF는 언제 사용할까?

Figma에서는 PDF로도 Export할 수 있다.

하지만 웹 프로젝트의 일반적인 이미지 Asset으로 PDF를 사용하는 경우는 많지 않다.

PDF는 오히려

```text
디자인 시안 공유

인쇄용 자료

문서

화면 설계 결과 전달
```

같은 상황에서 사용할 수 있다.

예를 들어 여러 화면을 정리해서

```text
UI 시안.pdf
```

형태로 전달하고 싶을 때 활용할 수 있다.

현재 Figma의 PDF Export는 SVG와 마찬가지로 1x만 지원한다.

---

## 그러면 WebP는?

웹 개발을 하다 보면 **WebP**도 자주 보게 된다.

나 역시 이미지 용량을 줄이거나 웹에서 사용할 이미지를 만들면서 WebP를 접했다.

그래서 자연스럽게

```text
Figma에서 WebP로 Export하면 되나?
```

라는 생각이 들 수 있다.

하지만 현재 Figma Design의 기본 정적 Export 형식은

```text
PNG

JPG

SVG

PDF
```

이다. WebP는 기본 Export 형식 목록에 포함되어 있지 않다.

따라서 WebP가 필요하다면 보통

```text
Figma
↓
PNG 또는 JPG Export
↓
WebP로 변환
↓
프로젝트에서 사용
```

같은 과정이 필요하다.

---

## 그렇다고 모든 이미지를 WebP로 바꿀 필요는 없다

이 부분도 처음에는

```text
WebP가 용량이 작다.
↓
그럼 전부 WebP
```

라고 생각하기 쉽다.

하지만 상황에 따라 다르다.

예를 들어

```text
UI 아이콘
```

이라면 WebP보다 SVG가 더 자연스러울 수 있다.

```text
사진
```

이라면 WebP가 좋은 선택이 될 수 있다.

즉 확장자를 하나로 통일하는 것보다

```text
이 이미지가 어떤 역할을 하는가?
```

를 기준으로 선택하는 것이 중요하다.

---

## 내가 간단하게 정리한 기준

| 용도        | 우선 고려                    |
| --------- | ------------------------ |
| UI 아이콘    | SVG                      |
| 단순 로고     | SVG                      |
| 벡터 심볼     | SVG                      |
| 투명 배경 그래픽 | PNG                      |
| 스크린샷      | PNG                      |
| 일반 사진     | JPG / 개발 단계에서 WebP 변환 고려 |
| 웹용 사진 최적화 | WebP 등 별도 최적화 고려         |
| 시안·문서 전달  | PDF                      |

물론 절대적인 규칙은 아니다.

하지만 무엇을 선택해야 할지 모를 때 출발점으로 사용하기에는 충분하다.

---

## 1x, 2x, 3x는 무엇일까?

PNG나 JPG Export를 보면 이런 옵션이 있다.

```text
0.5x

1x

2x

3x
```

처음에는 이것도 조금 헷갈렸다.

예를 들어 Figma에서 이미지가

```text
100 × 100
```

이라면

```text
1x
→ 100 × 100

2x
→ 200 × 200

3x
→ 300 × 300
```

처럼 더 큰 픽셀 크기로 Export할 수 있다.

[Figma](https://help.figma.com/hc/en-us/articles/13402894554519-Export-formats-and-settings-for-static-designs)는 고밀도 디스플레이용 이미지라면 더 큰 배율로 Export하는 것을 고려할 수 있다고 안내하고 있으며, 2x와 3x처럼 확대해서 Raster 이미지를 내보낼 수 있다.

---

## 그러면 무조건 3x가 좋은가?

처음에는 당연히

```text
3x
=
화질 좋음

그러면 3x가 최고
```

라고 생각했다.

하지만 이미지가 커지면 파일 용량도 증가할 수 있다.

웹에서는 이미지 하나하나의 용량도 페이지 로딩에 영향을 줄 수 있다.

따라서 필요 이상으로 큰 이미지를 사용하는 것도 좋은 방법은 아니다.

```text
화질

vs

파일 크기
```

사이의 균형이 필요하다.

---

## 웹에서는 실제 표시 크기도 중요하다

예를 들어 브라우저에서 이미지를

```text
200 × 200
```

정도로 보여줄 예정인데

```text
4000 × 4000
```

짜리 이미지를 넣는 것은 지나칠 수 있다.

브라우저에서는 결국 작게 보여주면서 훨씬 큰 데이터를 내려받게 될 수 있기 때문이다.

그래서 Raster 이미지를 Export할 때는

```text
실제로 어느 정도 크기로 보이는가?
```

를 함께 생각해야 한다.

---

## Figma에서는 고정 Width나 Height로도 Export할 수 있다

Export 배율을 반드시

```text
1x

2x
```

처럼만 설정해야 하는 것은 아니다.

현재 Figma에서는 값 뒤에

```text
x
w
h
```

를 붙여 Export 크기를 지정할 수 있다.

예를 들어

```text
2x
```

는 두 배율,

```text
800w
```

는 폭 800,

```text
600h
```

는 높이 600을 기준으로 Export하는 식이다.

특정 사이즈가 필요한 이미지라면 이 방식이 편하다.

---

## 투명 배경이 필요할 때 확인할 것

PNG나 SVG를 사용할 때는 배경을 투명하게 만들고 싶은 경우가 많다.

예를 들어 로고가

```text
흰색 Frame
└─ Logo
```

안에 있다고 해보자.

Frame 전체를 Export하면 흰 배경까지 포함될 수 있다.

그런데 내가 원하는 것이

```text
Logo만
```

이라면

```text
로고 Layer 자체 선택
```

또는 배경 Fill을 Export에서 제외하는 방법을 사용할 수 있다.

Figma는 Frame의 Fill에 대해 `Show in exports` 옵션을 끄면 Export 결과에서 해당 Fill을 숨길 수 있도록 지원한다.

이 부분을 모르고 있으면

```text
왜 투명 PNG로 저장했는데
흰 배경이 있지?
```

라고 생각할 수 있다.

---

## Frame 크기도 확인해야 한다

Export했는데 이미지 주변에 이상한 여백이 생기는 경우가 있다.

그럴 때는 파일 형식보다 먼저 Frame 자체를 확인해야 한다.

예를 들어

```text
┌─────────────────────┐
│                     │
│      [ Logo ]       │
│                     │
└─────────────────────┘
```

처럼 실제 Logo보다 Frame이 훨씬 크다면

Frame을 Export했을 때 그 빈 공간까지 같이 들어간다.

그래서

```text
무엇을 Export하고 있는가?
```

를 확인해야 한다.

```text
Logo Layer?

Logo Frame?

전체 화면 Frame?
```

에 따라 결과가 달라진다.

---

## Export 전에 Preview 확인하기

Export 버튼을 누르기 전에 Preview를 볼 수 있다.

별것 아닌 기능처럼 보이지만 실제로 꽤 유용하다.

특히

```text
배경이 포함됐는지

원하지 않는 요소가 들어갔는지

잘린 부분은 없는지

Export 범위가 맞는지
```

확인할 수 있다.

Figma에서는 하나의 선택 항목을 Export할 때 Preview를 통해 결과를 미리 확인할 수 있다.

몇 초만 확인하면

```text
Export
↓
파일 열어봄
↓
잘못됨
↓
다시 Figma
```

과정을 줄일 수 있다.

---

## 파일 이름도 중요했다

처음에는 파일 이름을 이렇게 만들기 쉽다.

```text
Frame 123.png

Group 87.svg

Rectangle 42.png
```

내 컴퓨터에 파일이 몇 개 없을 때는 괜찮다.

그런데 실제 프로젝트에 들어가면 문제가 생긴다.

```text
이게 무슨 이미지였지?
```

그래서 Figma에서 Layer 이름부터 제대로 정리하는 것이 좋았다.

예를 들면

```text
logo.svg

icon-search.svg

icon-settings.svg

empty-benefit.png

hero-cafe.jpg
```

처럼 역할이 보이도록 한다.

---

## 개발 파일 이름까지 생각하면서 Figma Layer 이름 정하기

Figma에서 Export하면 Layer 이름이 파일 이름으로 연결된다.

그래서 디자인할 때부터

```text
Search Icon
```

보다

```text
icon-search
```

처럼 개발 Asset 이름과 어느 정도 맞춰두는 방법도 있다.

프로젝트가 커지면

```text
icon-home.svg

icon-map.svg

icon-profile.svg
```

처럼 규칙이 있는 편이 관리하기 편하다.

---

## Figma에는 재미있는 파일명 기능도 있다

Figma에서는 `/`가 포함된 Layer 이름을 사용하면 Export할 때 해당 구조를 폴더처럼 만들 수도 있다.

예를 들어 Layer 이름을

```text
icons/navigation/home
```

으로 만들었다면 Export 결과에서 폴더 구조를 기준으로 정리할 수 있다. [Figma 공식 도움말](https://help.figma.com/hc/en-us/articles/360040028114-Export-from-Figma-Design)도 slash-separated naming을 사용하면 중첩 폴더 구조로 Export할 수 있다고 안내한다.

예를 들면

```text
icons/
└─ navigation/
   └─ home.svg
```

처럼 관리할 수 있다.

작은 프로젝트에서는 굳이 필요하지 않을 수 있지만 Asset이 많아지면 꽤 유용한 기능이다.

---

## 여러 형식을 한 번에 설정할 수도 있다

하나의 Asset을 여러 곳에서 사용해야 할 수도 있다.

예를 들어 로고를

```text
웹
→ SVG

문서
→ PNG
```

두 가지 형태로 쓰고 싶을 수 있다.

이때 Export 설정을 두 개 추가할 수 있다.

```text
Logo

Export
├─ SVG
└─ PNG 2x
```

그리고 한 번에 필요한 파일을 Export한다.

현재 Figma에서는 하나의 선택 항목에 여러 Export configuration을 추가할 수 있다.

---

## 여러 Asset을 한꺼번에 Export하기

프로젝트가 커지면

```text
아이콘 하나 저장

다음 아이콘 선택

또 저장
```

하는 것도 번거롭다.

Figma에서는 Export 설정이 지정된 여러 Asset을 한 번에 내보낼 수도 있다.

현재 전체 Export 설정 항목을 확인하는 단축키는

```text
Windows
Shift + Ctrl + E

Mac
Shift + Command + E
```

이다.

그러면 Export 설정이 지정된 Asset들을 확인한 뒤 필요한 항목을 한 번에 내보낼 수 있다.

아이콘이나 이미지가 많은 프로젝트에서는 이런 방식이 훨씬 편하다.

---

## Dev Mode에서도 Asset을 확인할 수 있다

디자이너와 개발자가 따로 작업하는 상황이라면 개발자가 직접 Figma Design을 수정할 필요는 없다.

Dev Mode에서 디자인의 크기나 스타일을 확인하고 필요한 Asset을 다운로드할 수 있다.

현재 Figma Dev Mode에서는 아이콘을 자동으로 감지해서 다운로드 가능한 Asset으로 보여줄 수도 있고, Export 설정이 적용된 Layer를 직접 내보낼 수도 있다.

이 구조를 보면 Figma가 단순 디자인 제작 도구만은 아니라는 것을 알 수 있다.

```text
디자이너
↓
Figma

개발자
↓
Dev Mode
↓
Asset / 크기 / 스타일 확인
↓
구현
```

처럼 디자인과 개발을 연결하는 공간이 된다.

---

## 원본 이미지와 Export 이미지는 다를 수 있다

Figma에 사진을 넣었다고 해보자.

그 사진을 Figma에서

```text
500 × 300
```

크기로 잘라서 사용했다.

개발자는 경우에 따라

```text
Figma에서 보이는 500 × 300 이미지
```

가 아니라

```text
처음 업로드했던 원본 이미지
```

가 필요할 수도 있다.

현재 Dev Mode에서는 선택한 이미지에 대해 Canvas에서 사용하는 크기로 다운로드하거나 원본 Source image file을 받을 수 있는 기능도 제공한다.

이미지를 실제 서비스에서 다시 가공할 계획이라면 이런 차이도 알아두는 것이 좋다.

---

## 이미지 안에 글자를 넣어서 Export할까?

디자인하면서 이런 방식도 가능하다.

```text
┌──────────────────┐
│ 오늘의 추천 카페 │
│     Coffee        │
└──────────────────┘
```

전체를 한 장의 PNG로 Export해서 웹에 넣는 것이다.

보기에는 Figma 화면과 완전히 똑같다.

하지만 실제 UI라면 보통 좋은 방법은 아니다.

왜냐하면 텍스트까지 이미지가 되어버리기 때문이다.

```text
글자 수정하기 어려움

반응형 대응 어려움

검색이나 접근성에 불리함

다국어 대응 어려움
```

같은 문제가 생긴다.

그래서 화면 전체를 하나의 이미지로 Export해서 개발하는 것이 아니라

```text
텍스트
→ 실제 HTML / React

버튼
→ 실제 UI Component

아이콘
→ SVG Asset

사진
→ 이미지 Asset
```

처럼 역할을 나누는 것이 중요했다.

---

## Figma 화면을 그대로 이미지로 만들면 개발이 아니다

처음에는 이런 생각도 할 수 있다.

```text
Figma에서 화면 완성
↓
전체 화면 PNG
↓
웹페이지에 넣음
```

그러면 정말 디자인과 똑같이 보인다.

하지만 사용자는 버튼을 누를 수 없고,

텍스트를 제대로 선택할 수도 없고,

화면 크기가 달라졌을 때 대응하기도 어렵다.

Figma 디자인을 개발로 가져간다는 것은

```text
Figma 화면 전체
→ 이미지
```

가 아니라

```text
Figma 화면
↓
구조 분석
↓
Component 구현
+
필요한 Asset만 Export
```

에 가깝다.

---

## Export해야 하는 것과 코드로 만들어야 하는 것 구분하기

이 기준도 처음에는 어려웠다.

예를 들어 화면에 이런 것이 있다고 해보자.

```text
로고

제목

검색 아이콘

카드

버튼

카페 사진
```

모두 Figma에 있지만 전부 이미지로 Export하는 것은 아니다.

내 기준으로 나누면

```text
로고
→ SVG

제목
→ 코드에서 Text

검색 아이콘
→ SVG

카드
→ CSS / React Component

버튼
→ CSS / React Component

카페 사진
→ 이미지 Asset
```

정도가 된다.

즉,

> **Figma에 있다고 해서 모두 Export하는 것은 아니다.**

이게 가장 중요한 부분 중 하나였다.

---

## 버튼도 이미지로 Export하면 안 될까?

버튼을 Figma에서 정말 예쁘게 만들었다고 해보자.

```text
[ 시작하기 ]
```

이 버튼 전체를 PNG로 Export하면 디자인은 그대로 유지된다.

하지만 버튼 문구가 바뀌면?

```text
시작하기
↓
러닝 시작
```

이미지를 다시 만들어야 한다.

버튼 크기가 달라지면?

다시 만들어야 한다.

다크모드가 생기면?

또 만들어야 한다.

그래서 일반적인 UI 요소는 이미지가 아니라 실제 코드로 구현하는 것이 좋다.

```html
<button>시작하기</button>
```

그리고 CSS나 Component를 이용해 Figma 디자인에 맞춘다.

---

## 아이콘도 코드로 만들 수 있는데 왜 Export할까?

여기서 또 궁금할 수 있다.

아이콘 라이브러리를 사용하면

```text
Lucide

Material Icons

Heroicons
```

같은 기존 아이콘을 사용할 수도 있다.

그렇다면 Figma 아이콘을 모두 Export할 필요는 없다.

프로젝트에서 사용하는 아이콘이 이미 라이브러리에 있다면

```text
Figma 아이콘
↓
어떤 아이콘인지 확인
↓
같은 라이브러리 아이콘 사용
```

하는 방법도 있다.

반대로 직접 만든

```text
브랜드 심볼

특수 아이콘

서비스 전용 그래픽
```

이라면 SVG로 Export해서 사용하는 편이 자연스럽다.

---

## 실제 개발에 넣기 전 파일 크기도 확인하기

Figma에서 Export가 잘됐다고 끝은 아니다.

특히 사진이나 큰 PNG는 파일 용량이 커질 수 있다.

예를 들어

```text
hero.png
5MB
```

같은 이미지를 웹페이지에 그대로 여러 장 사용하면 페이지가 무거워질 수 있다.

그래서 실제 개발에 넣을 때는

```text
Export
↓
파일 크기 확인
↓
필요하면 압축
↓
필요하면 WebP 등으로 변환
↓
프로젝트 추가
```

과정도 필요하다.

Figma에서 보기 좋은 이미지와

**서비스에서 빠르게 불러오는 이미지**

는 조금 다른 문제였다.

---

## Export 원본은 따로 보관하는 것이 좋았다

이미지를 최적화하면서

```text
PNG → WebP

JPG 압축

크기 축소
```

등을 하다 보면 원본이 필요할 때가 있다.

그래서 가능하면

```text
원본 Asset

↓

최적화된 실제 서비스 Asset
```

을 구분해 관리하는 편이 좋다.

예를 들어

```text
design-export/
└─ hero-original.png

public/images/
└─ hero.webp
```

처럼 나눌 수도 있다.

반드시 이런 구조여야 하는 것은 아니지만

```text
원본을 다시 구할 수 있는가?
```

는 생각해둘 필요가 있다.

---

## 프로젝트에 Asset을 넣을 때 이름 규칙도 만들기

Asset이 몇 개 없을 때는 이름이 크게 중요하지 않다.

```text
logo.png

image1.png
```

정도로 해도 된다.

하지만 프로젝트가 커지면

```text
image1.png

image2.png

image3.png

final.png

final2.png

real-final.png
```

같은 상황이 생길 수 있다.

그래서 처음부터 이름 규칙을 어느 정도 정하는 편이 좋다.

예를 들어

```text
logo-cuppick.svg

icon-location.svg

icon-search.svg

empty-benefit.png

hero-home.webp
```

처럼

```text
종류 + 역할
```

이 보이게 만든다.

---

## 같은 Asset을 중복으로 만들지 않기

화면마다 아이콘을 따로 Export하기 시작하면 이런 일이 생긴다.

```text
home-search.svg

detail-search.svg

map-search.svg
```

그런데 실제로는 같은 검색 아이콘이다.

그럴 필요가 없다.

```text
icon-search.svg
```

하나만 만들고 여러 화면에서 재사용하면 된다.

이건 Figma Component와도 연결된다.

디자인에서 반복되는 것은 Component로 관리하고,

개발에서도 반복되는 Asset은 하나를 재사용한다.

---

## 디자인과 개발의 이름을 맞춰두면 편하다

예를 들어 Figma에서는

```text
Icon / Navigation / Home
```

이라고 되어 있는데,

개발에서는

```text
house-final-new.svg
```

라고 되어 있으면 나중에 연결하기 어렵다.

가능하면

```text
Figma

icon-home
```

```text
Project

icon-home.svg
```

정도로 연결되게 관리하면 좋다.

특히 팀 프로젝트에서는

```text
이 아이콘 어디서 나온 거지?
```

를 찾는 시간을 줄일 수 있다.

---

## 내가 Export 전에 확인할 항목

정리하면서 간단한 체크리스트도 만들었다.

```text
1. 정말 이미지로 Export해야 하는가?

2. 코드로 구현해야 하는 UI는 아닌가?

3. PNG / JPG / SVG 중 무엇이 적합한가?

4. 투명 배경이 필요한가?

5. Frame에 불필요한 여백이 없는가?

6. Raster 이미지라면 필요한 해상도는 얼마인가?

7. 파일 이름이 역할을 설명하고 있는가?

8. 같은 Asset이 이미 존재하지 않는가?

9. Export 후 파일 용량은 적절한가?

10. 웹에 넣기 전에 추가 최적화가 필요한가?
```

이것만 확인해도 그냥

```text
PNG로 저장
```

하고 끝내는 것보다 훨씬 관리하기 쉬워진다.

---

## Figma Export를 처음 배울 때 기억할 것

파일 형식을 전부 외울 필요는 없다.

우선 이렇게 생각하면 충분하다.

```text
아이콘 / 로고
→ SVG 우선 검토

투명 이미지 / 그래픽
→ PNG

사진
→ JPG 또는 이후 WebP 최적화

문서 형태로 공유
→ PDF
```

그리고 Raster 이미지에서는

```text
1x

2x

3x
```

처럼 해상도를 조절할 수 있다.

하지만

```text
무조건 높은 배율
```

이 좋은 것은 아니다.

실제로 사용할 크기와 파일 용량을 같이 봐야 한다.

---

## Export를 배우면서 알게 된 것

처음에는 Figma Export를 단순한

```text
저장 기능
```

이라고 생각했다.

하지만 개발까지 연결해보니 조금 달랐다.

Export에서도 결국 판단해야 했다.

```text
이건 이미지인가?

코드로 만들어야 하는 UI인가?

Vector가 필요한가?

Raster가 필요한가?

어느 정도 해상도가 필요한가?

웹에 그대로 사용해도 되는가?

추가 최적화가 필요한가?
```

이런 판단이 필요했다.

즉 Figma에서

```text
Export
```

버튼 하나를 누르는 것보다

**무엇을 Export하지 않을 것인지 판단하는 것**

도 중요했다.

---

## 디자인 도구 공부를 마치며

첫 글부터 지금까지 내가 Figma를 배우면서 필요했던 기본적인 내용을 정리했다.

```text
01 개발자가 Figma를 배우는 이유

↓
02 Figma 기초

↓
03 Figma 교육 계정 활용

↓
04 Figma Make 활용

↓
05 디자인 레퍼런스 활용

↓
06 Figma Export
```

```text
디자이너가 쓰는 프로그램
```

이라고 생각했다.

하지만 직접 프로젝트를 만들면서 사용해보니

```text
아이디어

↓

화면 구조

↓

디자인

↓

Prototype

↓

Asset

↓

개발
```

을 연결해주는 도구라는 생각이 더 강해졌다.

그리고 여기서 다음 문제가 생겼다.

Figma에서 디자인은 만들었다.

이제 이것을 **실제 코드로 옮겨야 한다.**

직접 React와 CSS를 작성할 수도 있지만,

내 프로젝트에서는 Claude 같은 AI를 이용해서 Figma 디자인을 코드로 구현하는 방식도 사용하게 됐다.

그런데 단순히

```text
이 디자인 그대로 만들어줘.
```

라고 요청한다고 항상 원하는 결과가 나오는 것은 아니었다.

디자인을 AI에게 어떤 방식으로 전달하는지,

무엇을 고정하고 무엇을 구현하게 할지,

기존 디자인을 얼마나 정확하게 유지하도록 지시하는지가 중요했다.

다음 글에서는 디자인 도구 자체를 넘어

**Figma에서 만든 디자인을 Claude와 연결해서 실제 코드로 구현하는 과정**을 정리해보려고 한다.
