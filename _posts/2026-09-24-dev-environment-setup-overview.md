>
> 이 시리즈는 개발을 처음 시작한 당시의 실시간 기록이 아니라, 여러 프로젝트를 진행한 뒤 새 PC에서도 다시 구축할 수 있도록 기존 개발환경을 처음부터 확인하며 정리한 가이드다.
>
> 다만 07편 Tomcat은 다른 글과 달리 기존 환경을 다시 확인한 것이 아니라, 새로 구축하며 정리한 내용이다.

---

개발 공부를 처음 시작하면 생각보다 코드보다 먼저 해야 할 일이 많다.

강의에서는 갑자기 이런 프로그램들이 등장한다.

* VS Code
* IntelliJ IDEA
* Git
* GitHub
* SourceTree
* Node.js
* npm
* JDK
* Tomcat

처음 보면 이런 생각이 든다.

> 그래서 이걸 전부 설치해야 하는 건가?

> VS Code랑 IntelliJ는 둘 다 코드 작성 프로그램 아닌가?

> Git이랑 GitHub는 같은 건가?

> Node.js는 JavaScript인데 왜 설치해야 하지?

> Java를 공부하려는데 왜 JDK라는 걸 설치해야 하지?

> Tomcat은 또 어디에 쓰는 거지?

실제로 나도 개발 공부를 처음 시작했을 때는 프로그램을 하나씩 설치하기는 했지만, **각 프로그램이 왜 필요한지 정확히 이해하지 못한 상태에서 설치했던 경우가 많았다.**

그러다 보니 새로운 PC에서 환경을 다시 만들거나, 오류가 발생했을 때 무엇이 문제인지 찾기 어려웠다.

이번 글에서는 특정 프로그램을 바로 설치하기보다 먼저 **개발환경이라는 것이 무엇인지**, 그리고 앞으로 설치하게 될 프로그램들이 각각 어떤 역할을 하는지를 전체적으로 정리해보려고 한다.

이 글을 먼저 읽고 나면 이후 Git, VS Code, Node.js, JDK, IntelliJ, Tomcat을 설치할 때 조금 더 이해하기 쉬울 것이다.

---

## 개발환경이란?

개발환경은 간단히 말하면

> **코드를 작성하고, 실행하고, 저장하고, 관리하기 위해 필요한 프로그램과 설정을 모아놓은 환경**

이라고 생각하면 된다.

우리가 메모장만 가지고도 코드를 작성하는 것 자체는 가능하다.

예를 들어 JavaScript 코드를 메모장에 적을 수도 있고, Java 코드를 텍스트 파일에 작성할 수도 있다.

하지만 실제 개발에서는 단순히 글자를 입력하는 것만으로 끝나지 않는다.

작성한 코드를 실행해야 하고,

오류가 발생하면 확인해야 하고,

수정한 내용을 기록해야 하고,

다른 사람과 코드를 공유해야 하며,

프로젝트에 따라 서버를 실행해야 하는 경우도 있다.

그래서 개발을 할 때는 여러 도구를 함께 사용한다.

전체 구조를 먼저 단순하게 보면 다음과 같다.

```text
코드 작성
   ↓
VS Code / IntelliJ IDEA

프로그램 실행
   ↓
Node.js / JDK

코드 변경 기록
   ↓
Git

Git을 화면으로 쉽게 조작
   ↓
SourceTree

코드를 인터넷에 저장하고 공유
   ↓
GitHub

Java 웹 애플리케이션 실행
   ↓
Tomcat
```

조금 더 역할별로 묶으면 이렇게 볼 수 있다.

```text
개발환경

├─ 코드 작성
│  ├─ VS Code
│  └─ IntelliJ IDEA
│
├─ 프로그램 실행
│  ├─ Node.js
│  └─ JDK
│
├─ 버전 관리
│  ├─ Git
│  ├─ SourceTree
│  └─ GitHub
│
└─ Java 웹 애플리케이션 실행
   └─ Tomcat
```

처음부터 모든 프로그램의 기능을 외울 필요는 없다.

중요한 것은 각 프로그램이 **어떤 역할을 담당하는지 큰 그림을 먼저 이해하는 것**이다.

## 1. 코드를 작성하는 프로그램

우선 개발을 하려면 코드를 작성할 공간이 필요하다.

이때 사용하는 프로그램이 대표적으로 **VS Code와 IntelliJ IDEA**다.

### VS Code란?

VS Code의 정식 이름은 **Visual Studio Code**다.

Microsoft에서 만든 코드 편집기로, 다양한 프로그래밍 언어를 작성할 수 있다.

대표적으로 다음과 같은 작업에 많이 사용한다.

```text
HTML
CSS
JavaScript
TypeScript
React
Python
Markdown
JSON
```

VS Code는 기본 상태에서도 코드를 작성할 수 있지만, 필요한 기능을 **Extension(확장 프로그램)** 형태로 추가해서 사용할 수 있다는 특징이 있다.

예를 들어 HTML 파일을 작성하면서 브라우저에서 바로 확인하고 싶다면 Live Server 같은 확장 프로그램을 설치할 수 있다.

즉, VS Code는

> 필요한 기능을 추가하면서 사용하는 가벼운 코드 편집기

정도로 이해하면 된다.

### IntelliJ IDEA란?

IntelliJ IDEA 역시 코드를 작성하는 프로그램이다.

다만 Java나 Kotlin 개발에 특히 많이 사용한다.

Java 프로젝트를 만들고 실행하거나,

Spring Boot 프로젝트를 개발하거나,

JDK를 연결해서 프로그램을 실행하는 등 Java 개발에 필요한 기능이 많이 포함되어 있다.

처음에는 이렇게 생각하면 이해하기 쉽다.

```text
VS Code
→ 여러 언어를 편하게 작성할 수 있는 범용 코드 편집기

IntelliJ IDEA
→ Java 개발에 특히 강한 개발 도구
```

둘 중 하나만 반드시 사용해야 하는 것은 아니다.

프로젝트에 따라 둘을 모두 사용할 수도 있다.

예를 들어

```text
Frontend
HTML / CSS / JavaScript / React
→ VS Code

Backend
Java / Spring Boot
→ IntelliJ IDEA
```

처럼 나눠서 사용할 수 있다.

## 2. 작성한 코드를 실행하는 환경

코드를 작성했다고 해서 컴퓨터가 그 코드를 바로 이해하는 것은 아니다.

작성한 프로그램을 실제로 실행할 수 있도록 해주는 환경도 필요하다.

이번 환경 구축에서는 대표적으로 **Node.js와 JDK**를 설치한다.

---

## 3. Node.js란?

JavaScript는 원래 웹 브라우저 안에서 실행되는 언어였다.

예를 들어 웹사이트에서 버튼을 눌렀을 때 화면이 바뀌거나, 메뉴가 열리는 기능을 JavaScript로 만들 수 있다.

하지만 개발을 하다 보면 브라우저 밖에서도 JavaScript를 실행해야 하는 경우가 생긴다.

이때 사용하는 것이 Node.js다.

간단히 말하면

> **Node.js는 컴퓨터에서 JavaScript를 실행할 수 있도록 해주는 실행 환경**

이다.

Node.js를 설치하고 나면 터미널에서 JavaScript 프로그램을 실행할 수 있다.

예를 들어 다음과 같은 파일이 있다고 해보자.

```javascript
console.log("Hello Node.js");
```

Node.js가 설치되어 있다면 터미널에서

```bash
node app.js
```

처럼 실행할 수 있다.

### npm은 무엇일까?

Node.js를 설치하면 보통 **npm**도 함께 설치된다.

npm은 JavaScript 프로젝트에서 사용하는 패키지 관리 도구다.

처음에는

> 다른 사람이 만들어 놓은 JavaScript 라이브러리나 개발 도구를 설치하고 관리하는 프로그램

이라고 생각하면 된다.

예를 들어 React 프로젝트를 만들거나 필요한 라이브러리를 설치할 때 다음과 같은 명령어를 자주 보게 된다.

```bash
npm install
```

또는

```bash
npm run dev
```

처음에는 명령어 자체가 낯설 수 있지만, Node.js를 설치한 뒤 프로젝트를 진행하다 보면 자연스럽게 자주 사용하게 된다.

---

## 4. Java를 실행하기 위한 JDK

Java를 공부할 예정이라면 **JDK**를 설치하게 된다.

처음 보면 Java를 설치하는 것이 아니라 왜 JDK를 설치하는지 헷갈릴 수 있다.

JDK는

**Java Development Kit**

의 약자다.

말 그대로 Java 개발에 필요한 도구들을 모아놓은 패키지다.

Java 프로그램을 작성하고 실행하려면 대표적으로 다음 과정이 필요하다.

```text
Java 코드 작성
      ↓
컴파일
      ↓
실행
```

예를 들어

```text
Hello.java
```

라는 Java 파일을 만들었다고 해보자.

작성한 Java 코드는 바로 실행되는 것이 아니라 먼저 컴파일 과정을 거친다.

이때 JDK 안에 있는 `javac`라는 도구가 사용된다.

```bash
javac Hello.java
```

컴파일된 프로그램은 다시 Java 실행 환경을 통해 실행한다.

```bash
java Hello
```

그래서 JDK가 설치되어 있어야 Java 코드를 정상적으로 작성하고 컴파일하고 실행할 수 있다.

### JDK와 JRE는 무엇이 다를까?

Java를 공부하다 보면 JDK와 JRE라는 단어를 같이 보게 된다.

처음에는 아주 간단하게 다음 정도만 알고 있어도 충분하다.

```text
JRE
→ Java 프로그램을 실행하기 위한 환경

JDK
→ Java 프로그램을 개발하기 위한 도구
```

JDK에는 개발에 필요한 여러 도구가 들어 있기 때문에 Java 개발자는 일반적으로 JDK를 설치한다.

이번 시리즈에서는 **JDK 21을 기준으로 개발환경을 구축**할 예정이다.

## 5. Git이란?

개발을 하다 보면 코드를 계속 수정하게 된다.

예를 들어 처음에는 이런 코드였다고 해보자.

```text
첫 번째 버전
```

그다음 기능을 추가한다.

```text
두 번째 버전
```

다시 오류를 수정한다.

```text
세 번째 버전
```

이런 변경 내용을 파일 이름으로 관리하기 시작하면 상황이 복잡해진다.

```text
project_final

project_final2

project_final_real

project_final_real2

project_final_last

project_final_last_real
```

이런 방식 대신 개발에서는 **Git**이라는 도구를 사용한다.

Git은

> **파일의 변경 내용을 기록하고 관리하는 버전 관리 시스템**

이다.

Git을 사용하면 코드가 어떻게 변경됐는지 기록할 수 있다.

예를 들어

```text
로그인 화면 추가

↓

버튼 디자인 수정

↓

로그인 오류 수정

↓

회원가입 기능 추가
```

같은 개발 과정을 하나씩 기록할 수 있다.

필요하다면 이전 상태를 확인할 수도 있고, 여러 명이 같은 프로젝트를 작업할 때 각자의 변경 내용을 관리할 수도 있다.

---

## 6. GitHub는 Git과 무엇이 다를까?

Git과 GitHub는 이름이 비슷해서 처음에는 같은 프로그램처럼 느껴질 수 있다.

하지만 역할이 다르다.

Git은

> 내 컴퓨터에서 코드의 변경 이력을 관리하는 도구

이고,

GitHub는

> Git으로 관리하는 프로젝트를 인터넷에 저장하고 공유할 수 있는 서비스

라고 생각하면 된다.

간단히 비교하면 다음과 같다.

```text
Git
→ 내 컴퓨터에서 변경 기록 관리

GitHub
→ Git 프로젝트를 인터넷에 저장
```

GitHub에 프로젝트를 올리면 다른 컴퓨터에서도 프로젝트를 받을 수 있다.

팀 프로젝트를 한다면 팀원들과 같은 저장소를 공유할 수도 있다.

### 저장소 Repository

Git과 GitHub를 공부하면 **Repository**, 줄여서 `repo`라는 단어를 자주 보게 된다.

Repository는 쉽게 말하면

> Git으로 관리하는 프로젝트 저장 공간

이다.

예를 들어 블로그 프로젝트가 하나 있다면

```text
my-blog
```

라는 하나의 Repository가 있을 수 있다.

이 저장소 안에서 코드 변경 내용을 Git으로 관리하고, GitHub에 올려 인터넷에서도 보관할 수 있다.

---

## 7. SourceTree는 무엇일까?

Git은 기본적으로 명령어로 사용할 수 있다.

예를 들어 터미널에서 다음과 같은 명령어를 사용한다.

```bash
git status
```

```bash
git add .
```

```bash
git commit
```

```bash
git push
```

처음 Git을 공부하면 이러한 명령어들이 어렵게 느껴질 수 있다.

SourceTree는 Git을 **화면으로 사용할 수 있게 도와주는 프로그램**이다.

즉,

```text
Git
→ 실제 버전 관리 기능

SourceTree
→ Git을 GUI 화면으로 사용할 수 있게 해주는 프로그램
```

이다.

여기서 GUI는

**Graphical User Interface**

의 약자로, 명령어 대신 버튼이나 화면을 통해 프로그램을 조작하는 방식을 말한다.

SourceTree에서는 Git의 변경 내용을 화면으로 확인할 수 있고,

Commit이나 Push 같은 작업도 버튼을 이용해서 할 수 있다.

그렇다고 SourceTree가 Git을 대신하는 것은 아니다.

실제 버전 관리 기능은 Git이 담당하고,

SourceTree는 Git을 보다 쉽게 사용할 수 있도록 도와주는 역할이다.

---

## 8. Tomcat은 무엇일까?

Tomcat은 이번 개발환경 중에서 특히 처음 접하면 역할이 이해하기 어려울 수 있다.

Tomcat은 Java 웹 애플리케이션을 실행할 때 사용하는 프로그램이다.

예를 들어 일반적인 Java 프로그램은 다음처럼 실행할 수 있다.

```text
Java 코드
   ↓
JDK
   ↓
프로그램 실행
```

하지만 웹 애플리케이션에서는 사용자가 브라우저를 통해 서버에 요청을 보내고, 서버가 그 요청을 처리해서 결과를 다시 전달해야 한다.

```text
브라우저
   ↓
요청

Tomcat
   ↓

Java 웹 애플리케이션

   ↓
응답

브라우저
```

Tomcat은 이런 Java 웹 애플리케이션을 실행하는 데 사용되는 **서블릿 컨테이너**다.

처음에는 용어를 완벽하게 이해할 필요는 없다.

우선

> **Java로 만든 웹 프로그램을 서버처럼 실행할 때 사용하는 프로그램**

이라고 이해하면 충분하다.

Tomcat의 구체적인 설치와 설정, 실행 방법은 07편 Tomcat 환경 구축 글에서 다룬다.

## 9. localhost는 무엇일까?

개발환경을 구축하다 보면 `localhost`라는 단어도 자주 등장한다.

localhost는 쉽게 말하면

> **현재 사용하고 있는 내 컴퓨터**

를 의미한다.

웹사이트는 일반적으로 인터넷에 있는 서버에 접속한다.

예를 들어

```text
사용자 컴퓨터
   ↓
인터넷
   ↓
웹 서버
```

형태다.

하지만 개발 중에는 아직 인터넷에 서비스를 배포하지 않고 내 컴퓨터에서 먼저 실행해본다.

이때

```text
localhost
```

를 이용한다.

즉,

```text
http://localhost
```

에 접속한다는 것은

> 현재 내 컴퓨터에서 실행 중인 웹 서버에 접속한다

는 의미다.

Tomcat뿐 아니라 Node.js, React, Spring Boot 등을 공부할 때도 localhost를 계속 만나게 된다.

---

## 10. PATH와 환경변수는 왜 설정할까?

JDK나 Node.js 설치 글을 보면 `PATH`, `JAVA_HOME`, 환경변수 같은 단어가 자주 등장한다.

처음에는 상당히 복잡하게 느껴질 수 있다.

하지만 원리는 생각보다 단순하다.

예를 들어 Node.js가 설치되어 있다고 해보자.

터미널에서 다음 명령어를 입력한다.

```bash
node -v
```

그러면 컴퓨터는 `node`라는 프로그램이 어디에 있는지 찾아야 한다.

이때 PATH에 Node.js의 위치가 등록되어 있다면 컴퓨터가 해당 프로그램을 찾을 수 있다.

즉,

```text
node 실행 요청

↓

Windows가 PATH 확인

↓

Node.js 설치 위치 발견

↓

Node.js 실행
```

과 같은 과정이다.

JDK도 비슷하다.

```bash
java -version
```

명령어를 실행했을 때 Java를 찾을 수 있도록 환경 설정이 필요하다.

그래서 JDK 설치 과정에서는 보통

```text
JAVA_HOME
PATH
```

같은 환경변수를 설정한다.

자세한 설정 방법은 JDK 환경 구축 글에서 직접 진행할 예정이다.

---

## 11. 터미널은 무엇일까?

개발환경을 구축하면 터미널을 사용할 일이 많아진다.

터미널은 글자로 명령어를 입력해서 컴퓨터를 조작하는 공간이다.

예를 들어 Node.js 버전을 확인하려면

```bash
node -v
```

Git 버전을 확인하려면

```bash
git --version
```

Java 버전을 확인하려면

```bash
java -version
```

처럼 명령어를 입력한다.

VS Code 안에서도 터미널을 열 수 있고,

Windows Terminal,

명령 프롬프트,

PowerShell,

Git Bash

등 여러 종류의 터미널을 사용할 수 있다.

처음에는 각각의 차이를 완벽하게 알 필요는 없다.

중요한 것은

> 개발 과정에서는 화면에서 버튼만 누르는 것이 아니라 터미널에서 직접 명령어를 실행하는 작업도 많다

는 점이다.

## 12. 앞으로 구축할 개발환경

이번 Dev Setup 시리즈에서는 다음 순서대로 환경을 구축한다.

### 00. 개발환경 구축 전체 가이드

현재 글이다.

개발환경이 무엇인지 알아보고, 앞으로 설치할 프로그램의 역할과 전체 구조를 먼저 이해한다.

### 01. Git & GitHub 환경 구축

Git을 설치하고 GitHub와 연결한다.

주요 내용은 다음과 같다.

```text
Git과 GitHub 차이
↓
Git 설치
↓
Git Bash 확인
↓
사용자 이름 설정
↓
사용자 이메일 설정
↓
GitHub 연결
↓
설치 정상 여부 확인
```

이 글에서는 Git의 세부적인 사용법보다는 **Git을 사용할 수 있는 환경을 만드는 것**에 집중한다.

Commit, Branch, Push, Pull, PR 같은 Git 사용법은 Git & GitHub 카테고리에서 별도로 정리한다.

### 02. SourceTree 환경 구축

Git을 GUI로 사용할 수 있도록 SourceTree를 설치한다.

```text
SourceTree란?
↓
왜 사용하는가?
↓
설치
↓
Git 연결
↓
GitHub 연결
↓
Repository 열기
```

Git 명령어와 함께 SourceTree의 화면을 비교해보면 Git의 동작을 이해하는 데도 도움이 된다.

### 03. VS Code 환경 구축

웹 개발이나 다양한 프로그래밍 언어를 작성할 때 사용할 VS Code를 설치한다.

```text
VS Code 설치
↓
PATH 설정 확인
↓
터미널 사용
↓
기본 설정
↓
Extension 설치
↓
파일 만들기
↓
첫 코드 실행
```

VS Code를 설치한 뒤 HTML, CSS, JavaScript 등을 공부할 때 계속 사용하게 된다.

### 04. Node.js 환경 구축

JavaScript를 컴퓨터에서 실행할 수 있도록 Node.js를 설치한다.

```text
Node.js란?
↓
npm이란?
↓
LTS 버전 설치
↓
node 버전 확인
↓
npm 버전 확인
↓
첫 JavaScript 실행
```

이후 React나 Next.js 같은 기술을 사용할 때도 Node.js가 필요하다.

### 05. JDK 21 환경 구축

Java 개발을 위한 JDK를 설치한다.

```text
Java / JDK / JRE 차이
↓
JDK 21 설치
↓
JAVA_HOME 설정
↓
PATH 설정
↓
java 버전 확인
↓
javac 버전 확인
↓
첫 Java 프로그램 실행
```

환경변수까지 직접 설정하고 정상적으로 Java가 실행되는지 확인한다.

### 06. IntelliJ IDEA 환경 구축

Java 개발에 사용할 IntelliJ IDEA를 설치한다.

```text
IDE란?
↓
IntelliJ 설치
↓
JDK 연결
↓
Java 프로젝트 생성
↓
Java 파일 작성
↓
프로그램 실행
```

JDK와 IntelliJ의 역할이 서로 어떻게 연결되는지도 함께 확인한다.

### 07. Tomcat 환경 구축

Java 웹 애플리케이션을 실행하기 위한 Tomcat 환경을 만든다.

```text
웹 서버란?
↓
Tomcat이란?
↓
서블릿 컨테이너란?
↓
Tomcat 설치
↓
JDK 연결
↓
Tomcat 실행
↓
localhost 접속
```

직접 서버를 실행하고 브라우저에서 결과를 확인한다.

### 08. 새 PC에서 개발환경 다시 구축하기

마지막 글은 지금까지 설치했던 프로그램들을 한 번에 다시 확인할 수 있는 체크리스트 형태로 정리한다.

컴퓨터를 바꾸거나,

Windows를 다시 설치하거나,

학교나 회사의 새로운 컴퓨터에서 환경을 구축해야 할 때 참고하기 위한 글이다.

예를 들어 다음과 같은 형태다.

```text
□ Git 설치
□ git --version 확인

□ GitHub 연결 확인

□ SourceTree 설치
□ Repository 연결 확인

□ VS Code 설치
□ 터미널 정상 실행 확인

□ Node.js 설치
□ node -v 확인
□ npm -v 확인

□ JDK 21 설치
□ java -version 확인
□ javac -version 확인

□ IntelliJ IDEA 설치
□ JDK 연결 확인

□ Tomcat 설치
□ 서버 실행 확인
□ localhost 접속 확인
```

## 13. 설치 순서가 중요한 이유

각 프로그램은 완전히 독립되어 있는 것처럼 보이지만 실제로는 서로 연결되어 있다.

예를 들어 IntelliJ에서 Java 프로그램을 실행하려면 JDK가 필요하다.

```text
JDK 설치
   ↓
IntelliJ 설치
   ↓
IntelliJ에 JDK 연결
   ↓
Java 프로젝트 실행
```

SourceTree도 Git을 기반으로 동작한다.

```text
Git 설치
   ↓
SourceTree 설치
   ↓
Git 연결
```

따라서 가능하면 순서를 정해서 설치하는 것이 좋다.

이번 시리즈에서는 다음 순서를 기준으로 진행한다.

```text
Git & GitHub
      ↓
SourceTree
      ↓
VS Code
      ↓
Node.js
      ↓
JDK 21
      ↓
IntelliJ IDEA
      ↓
Tomcat
```

이 순서를 반드시 지켜야만 설치가 가능한 것은 아니다.

다만 처음 개발환경을 만드는 경우에는 의존 관계를 이해하면서 진행하기 좋기 때문에 이 순서로 정리했다.

## 14. 모든 프로그램을 지금 당장 사용할까?

개발환경을 구축하면서 이런 생각이 들 수도 있다.

> 아직 Java를 시작하지 않았는데 JDK를 왜 설치하지?

> Tomcat은 당장 사용하지 않을 것 같은데?

맞다.

설치한 모든 프로그램을 처음부터 동시에 사용하는 것은 아니다.

공부하는 내용에 따라 필요한 프로그램이 달라진다.

예를 들어 HTML과 CSS를 공부하는 단계에서는 주로 VS Code를 사용할 수 있다.

```text
HTML
CSS
JavaScript
   ↓
VS Code
```

Java를 공부하기 시작하면 JDK와 IntelliJ를 사용하게 된다.

```text
Java
   ↓
JDK
   +
IntelliJ
```

Git을 이용해서 코드를 기록하기 시작하면 Git과 GitHub를 사용한다.

```text
프로젝트
   ↓
Git
   ↓
GitHub
```

따라서 처음에는 사용하지 않더라도 앞으로 공부하면서 하나씩 연결된다고 보면 된다.

## 15. 설치보다 중요한 것은 정상 작동 확인

개발 프로그램은 설치 버튼을 눌렀다고 끝난 것이 아니다.

설치 후 반드시 정상적으로 작동하는지 확인해야 한다.

예를 들어 Git을 설치했다면

```bash
git --version
```

Node.js를 설치했다면

```bash
node -v
npm -v
```

JDK를 설치했다면

```bash
java -version
javac -version
```

처럼 확인한다.

프로그램이 설치되어 있어도 PATH 설정이 잘못되어 있으면 터미널에서 명령어를 찾지 못할 수 있다.

따라서 앞으로 작성할 설치 글에서는 항상

```text
설치
↓
설정
↓
버전 확인
↓
직접 실행
```

순서까지 진행한다.

단순히 프로그램 설치 화면까지만 따라가는 것이 아니라 **실제로 사용할 수 있는 상태인지 확인하는 것**이 목표다.

---

## 16. 버전은 기록해두기

개발환경을 구축할 때는 설치한 프로그램의 버전을 기록해두는 것도 좋다.

예를 들어 같은 Java라고 해도 프로젝트마다 사용하는 JDK 버전이 다를 수 있다.

Node.js 역시 프로젝트마다 요구하는 버전이 다를 수 있다.

그래서 개발환경을 구축한 뒤 다음과 같이 기록해두면 나중에 도움이 된다.

```text
Git:
git --version

Node.js:
node -v

npm:
npm -v

Java:
java -version

Java Compiler:
javac -version
```

오류가 발생했을 때

> 내 컴퓨터에서는 왜 안 되지?

라는 상황이 생기면 가장 먼저 확인하는 것 중 하나가 바로 버전이다.

---

## 17. 개발환경 구축에서 자주 생기는 문제

처음 개발환경을 만들 때 발생하는 문제는 대부분 몇 가지 유형으로 반복된다.

### 프로그램은 설치했는데 명령어가 실행되지 않는다

예를 들어

```bash
java -version
```

을 실행했는데 Java를 찾을 수 없다는 오류가 발생할 수 있다.

이 경우 프로그램 설치 자체보다 **PATH 환경변수 문제**일 가능성이 있다.

### 여러 버전이 설치되어 있다

Java나 Node.js를 여러 번 설치하다 보면 여러 버전이 동시에 존재할 수 있다.

이 경우 내가 원하는 버전이 아니라 다른 버전이 실행되는 문제가 생길 수 있다.

그래서 설치 후에는 반드시 버전을 확인해야 한다.

### 프로그램마다 설정된 경로가 다르다

예를 들어 JDK는 설치되어 있지만 IntelliJ가 해당 JDK를 사용하도록 설정되어 있지 않을 수 있다.

즉,

```text
JDK 설치 완료
```

와

```text
IntelliJ에서 JDK 사용 가능
```

은 완전히 같은 의미가 아니다.

프로그램끼리 연결하는 설정이 필요한 경우도 있다.

### 설치 화면을 그대로 넘긴다

설치 프로그램에서는 여러 선택지가 등장한다.

처음에는 무조건 `Next`만 눌러도 될 것처럼 보이지만 PATH 등록이나 설치 위치처럼 중요한 옵션이 있을 수 있다.

그래서 이후 글에서는 설치 화면에서 어떤 항목을 선택해야 하는지도 함께 확인할 예정이다.

---

## 18. 개발환경을 한 번 직접 만들어보는 이유

요즘은 프로그램 하나만 설치하면 개발환경을 자동으로 구성해주는 도구도 많다.

하지만 처음 개발을 공부할 때는 한 번 정도는 직접 환경을 구성해보는 것이 좋다고 생각한다.

그래야 이후 문제가 발생했을 때

```text
코드 문제인가?

VS Code 문제인가?

Node.js 문제인가?

JDK 문제인가?

환경변수 문제인가?

Git 문제인가?

서버 문제인가?
```

를 어느 정도 구분할 수 있기 때문이다.

개발환경 구축 자체도 개발 공부의 일부다.

코드만 작성하는 것이 아니라,

내 코드가 **어디에서 작성되고, 무엇을 통해 실행되며, 어떻게 저장되고 관리되는지**를 이해하는 과정이라고 생각하면 된다.

## 정리

이번 글에서는 실제 설치를 시작하기 전에 개발환경의 전체 구조를 먼저 정리했다.

앞으로 사용할 프로그램의 역할을 다시 정리하면 다음과 같다.

| 프로그램 | 역할 |
|------|------|
| VS Code | 여러 언어의 코드를 작성하는 코드 편집기 |
| IntelliJ IDEA | Java 개발에 강한 IDE |
| Node.js | JavaScript를 컴퓨터에서 실행하는 환경 |
| npm | JavaScript 패키지를 설치하고 관리하는 도구 |
| JDK | Java 프로그램을 개발하고 실행하기 위한 도구 |
| Git | 코드 변경 이력을 관리하는 버전 관리 시스템 |
| SourceTree | Git을 화면으로 쉽게 사용할 수 있게 해주는 GUI 도구 |
| GitHub | Git 저장소를 인터넷에 저장하고 공유하는 서비스 |
| Tomcat | Java 웹 애플리케이션을 실행하는 서블릿 컨테이너 |

전체 흐름은 다음처럼 기억하면 된다.

```text
코드를 작성한다
→ VS Code / IntelliJ

작성한 프로그램을 실행한다
→ Node.js / JDK

코드 변경 내용을 기록한다
→ Git

Git을 화면으로 관리한다
→ SourceTree

프로젝트를 인터넷에 저장하고 공유한다
→ GitHub
```
