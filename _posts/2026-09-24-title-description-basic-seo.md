OG 이미지와 링크 미리보기를 정리하면서 자연스럽게 페이지의 `title`과 `description`도 다시 보게 됐다.

처음 블로그를 만들 때는 화면에 보이는 제목만 잘 작성하면 된다고 생각했다.

포스트 안에 큰 제목이 있고, 글 내용이 잘 보이면 충분하다고 봤다.

하지만 브라우저 탭이나 링크 미리보기처럼 페이지 바깥에서 블로그가 어떻게 보이는지 확인하다 보니 **웹페이지에는 화면에 직접 보이지 않는 정보도 필요하다**는 것을 알게 됐다.

그중 가장 기본적인 것이 페이지의 `title`과 `description`이었다.

그리고 이 정보를 정리하다 보니 자연스럽게 SEO라는 개념까지 이어졌다.

---

## 화면의 제목과 페이지 title은 역할이 달랐다

포스트에는 이미 제목이 있다.

예를 들어 글 안에는 이렇게 보일 수 있다.

```text
OG 이미지와 링크 미리보기 설정하기
```

처음에는 이 제목만 있으면 된다고 생각했다.

하지만 브라우저 탭에서 사용하는 제목은 별도로 존재한다.

HTML에서는 보통 `<title>`을 통해 정한다.

```html
<title>OG 이미지와 링크 미리보기 설정하기 | MY-BLOG</title>
```

이 값은 본문 위에 표시되는 큰 제목과는 역할이 다르다.

브라우저 탭에서 현재 페이지를 구분할 때 사용되고, 검색 결과나 다른 서비스에서도 페이지를 설명하는 정보로 활용될 수 있다.

그래서

```text
본문 제목
→ 글을 읽는 사람에게 보여주는 제목

title
→ 브라우저와 외부 서비스에도 페이지를 설명하는 제목
```

정도로 구분하니 이해하기 쉬웠다.

---

## 모든 페이지가 같은 title이면 불편했다

블로그 이름만 넣어서 모든 페이지를

```text
MY-BLOG
```

로 표시할 수도 있다.

사이트 자체는 정상적으로 동작한다.

하지만 탭을 여러 개 열어두면 문제가 생긴다.

```text
MY-BLOG
MY-BLOG
MY-BLOG
MY-BLOG
```

어느 탭이 어떤 포스트인지 알기 어렵다.

그래서 포스트 페이지에서는 글 제목과 블로그 이름을 함께 보여주는 방식이 더 자연스러웠다.

```text
카테고리 접기·펼치기 기능 만들기 | MY-BLOG
방문자 코멘트 기능 고민하기 | MY-BLOG
개발 블로그에 검색 기능은 필요할까 | MY-BLOG
```

홈처럼 사이트 자체를 대표하는 페이지와 개별 포스트는 title의 역할도 조금 달랐다.

**페이지마다 자신이 무엇인지 설명할 수 있어야 했다.**

---

## description은 페이지를 짧게 설명하는 정보였다

`description`도 처음에는 낯선 정보였다.

페이지 안에서 본문처럼 직접 보이는 내용이 아니기 때문이다.

보통은 이런 형태로 작성할 수 있다.

```html
<meta
  name="description"
  content="개발 블로그의 검색 기능이 필요한 이유와 카테고리와의 차이를 정리한 글입니다."
>
```

페이지의 내용을 짧게 설명하는 문장이다.

검색 결과나 링크를 처리하는 서비스가 이 정보를 참고할 수 있다.

중요한 것은 description이 **본문을 대신하는 설명이 아니라 페이지를 빠르게 이해하기 위한 요약 정보**라는 점이었다.

---

## description을 너무 거창하게 쓰고 싶지는 않았다

SEO를 검색하다 보면 특정 키워드를 몇 번 넣어야 한다거나 검색에 잘 노출되는 문장을 만들어야 한다는 이야기가 많이 나온다.

처음에는 description도 그런 식으로 작성해야 하나 싶었다.

하지만 내 블로그에서는 검색 순위를 높이기 위한 문구를 억지로 만드는 것보다 실제 글의 내용을 정확하게 설명하는 것이 먼저라고 생각했다.

예를 들어

```text
개발 블로그 검색 기능 구현 방법과 SEO 최적화,
최고의 블로그 운영 노하우를 알아봅니다.
```

처럼 실제 글보다 크게 표현하고 싶지는 않았다.

차라리

```text
포스트가 늘어나면서 검색 기능이 필요해진 이유와
카테고리와 검색의 역할 차이를 정리했다.
```

처럼 **실제로 글에서 다루는 내용을 짧게 설명하는 편**이 내 블로그와 더 잘 맞았다.

---

## title과 description도 중복해서 관리하고 싶지는 않았다

포스트에는 이미 제목이 있다.

그런데 페이지 title을 따로 입력하고, OG title도 다시 입력하고, 또 다른 곳에서도 같은 제목을 작성하면 관리할 값이 계속 늘어난다.

```text
포스트 제목
title
og:title
```

내용은 거의 같은데 각각 직접 입력하면 나중에 제목을 수정했을 때 하나를 놓칠 수도 있다.

그래서 가능한 경우 기존 포스트 정보를 활용하는 편이 자연스러웠다.

```text
포스트 title
        ↓
페이지 title
        ↓
og:title
```

필요하면 표시 형식만 조금 다르게 만들면 된다.

예를 들어 실제 포스트 제목이

```text
title·description과 기본 SEO 설정하기
```

라면 브라우저에서는

```text
title·description과 기본 SEO 설정하기 | MY-BLOG
```

처럼 블로그 이름을 덧붙일 수 있다.

같은 정보를 여러 번 작성하지 않으니 관리하기도 편했다.

---

## SEO라는 말을 처음 보면 일이 굉장히 커 보였다

`SEO`는 Search Engine Optimization, 검색 엔진 최적화를 의미한다.

처음 이 단어를 보면 검색 결과 상위에 노출시키기 위한 굉장히 복잡한 기술처럼 느껴진다.

실제로 SEO에는 생각해야 할 것이 많다.

하지만 개인 개발 블로그를 만드는 내 입장에서 처음부터 모든 것을 다룰 필요는 없었다.

우선은 훨씬 기본적인 것부터 볼 수 있었다.

```text
페이지마다 적절한 title이 있는가?

페이지의 내용을 설명하는 description이 있는가?

제목 구조가 이상하지 않은가?

주소가 정상적으로 유지되는가?

이미지에 필요한 설명이 있는가?

페이지 내용을 검색 서비스가 이해할 수 있는가?
```

이 정도만 봐도 이미 기본적인 웹페이지 품질과 연결되어 있었다.

그래서 처음부터 'SEO를 완벽하게 한다'가 아니라 **검색엔진도 페이지 내용을 이해할 수 있도록 기본 정보를 정리한다**는 방향으로 접근했다.

---

## SEO를 위해 글 제목을 이상하게 바꾸고 싶지는 않았다

검색 노출을 생각하기 시작하면 제목에 키워드를 많이 넣고 싶어질 수 있다.

예를 들어 원래 쓰고 싶은 제목이

```text
Git pull이 헷갈렸던 이유
```

인데 검색을 의식하다 보면

```text
Git Pull 사용법 총정리 | GitHub 브랜치 Pull 명령어 완벽 가이드
```

처럼 바뀔 수도 있다.

검색에는 도움이 될 수도 있겠지만 내 실제 글의 성격과 맞지 않을 수 있다.

내 블로그는 공부하면서 헷갈렸던 과정과 이해한 내용을 기록하는 공간이다.

그래서 SEO 때문에 글의 성격까지 바꾸고 싶지는 않았다.

검색엔진을 고려하더라도 **사람이 읽었을 때 자연스러운 제목이 먼저**라고 생각했다.

---

## 제목 구조도 기본적인 부분이었다

본문에서는 `h1`, `h2`, `h3` 같은 제목 구조를 사용한다.

처음에는 단순히 글씨 크기를 조절하는 태그처럼 생각하기 쉬웠다.

하지만 실제로는 문서의 구조를 표현하는 역할도 한다.

예를 들면

```text
H1  포스트 제목

H2  검색 기능이 필요한 이유
H2  카테고리와 검색의 차이

    H3  카테고리
    H3  검색
```

처럼 글의 관계를 나타낼 수 있다.

이 구조가 정리되어 있으면 사람도 긴 글을 이해하기 쉽고, 페이지 내용을 해석하는 프로그램 입장에서도 구조가 더 명확해진다.

앞에서 TOC를 만들기 위해 소제목 구조를 정리했던 것이 기본 SEO와도 자연스럽게 이어졌다.

---

## 이미지의 alt도 다시 보게 됐다

이미지에 사용하는 `alt` 역시 SEO를 공부하면서 자주 등장했다.

하지만 단순히 검색 노출을 위한 값으로 생각하고 싶지는 않았다.

`alt`는 이미지가 보이지 않거나 이미지를 직접 확인하기 어려운 환경에서 무엇을 보여주는 이미지인지 전달하는 역할도 한다.

```html
<img
  src="category-toggle.png"
  alt="사이드바 카테고리가 펼쳐진 화면"
/>
```

`image1`, `screenshot`처럼 파일 자체를 설명하는 말보다 이미지가 **무엇을 보여주고 있는지** 적는 편이 더 의미가 있었다.

SEO 때문에 새롭게 생긴 규칙이라기보다 원래 웹페이지를 제대로 만드는 데 필요한 기본에 가까웠다.

---

## URL도 가능하면 의미를 유지하고 싶었다

검색엔진뿐 아니라 실제 사용자도 URL을 보게 된다.

링크를 복사할 수도 있고 다른 문서에 남겨둘 수도 있다.

그래서 포스트 주소가 일정한 규칙을 유지하는 것도 중요하다고 느꼈다.

특히 이미 공개된 글의 URL을 이유 없이 자주 바꾸면 이전에 공유했던 링크가 문제가 될 수 있다.

디자인은 언제든 바꿀 수 있지만 주소는 외부에서 사용되기 시작하면 조금 더 조심해야 했다.

이때부터 URL을 단순한 내부 경로가 아니라 **외부와 연결되는 주소**로 보게 됐다.

---

## OG 설정과 SEO 정보는 서로 연결되는 부분이 많았다

앞에서 OG 이미지를 설정하면서 `og:title`, `og:description` 같은 값을 봤다.

이번에 `title`과 `description`을 정리하고 나니 두 작업이 완전히 따로 있는 것은 아니라는 것을 알게 됐다.

예를 들어 하나의 포스트가 있다면

```text
포스트 제목
        ↓
페이지 title
        ↓
og:title

포스트 설명
        ↓
meta description
        ↓
og:description
```

처럼 같은 정보를 여러 환경에서 활용할 수 있다.

차이가 있다면 사용하는 목적이다.

일반적인 `title`과 `description`은 페이지 자체를 설명하는 기본 정보이고,

OG 정보는 특히 외부에 링크가 공유될 때 페이지를 소개하는 데 사용된다.

처음부터 각각 별개의 기능처럼 만들기보다 **포스트의 기본 정보를 중심으로 연결하는 편**이 관리하기 쉬웠다.

---

## 검색엔진에 잘 보이는 것보다 먼저 사람이 이해할 수 있어야 했다

SEO를 공부하면 검색엔진을 계속 의식하게 된다.

하지만 블로그 글을 실제로 읽는 것은 결국 사람이다.

검색엔진을 위해 제목을 어색하게 만들거나 description에 같은 단어를 반복하는 방향은 원하지 않았다.

내가 생각한 우선순위는 단순했다.

```text
1. 사람이 글의 내용을 쉽게 이해한다.

2. 페이지 구조를 명확하게 만든다.

3. 그 구조를 검색엔진도 이해할 수 있게 기본 정보를 제공한다.
```

검색엔진 때문에 완전히 다른 글쓰기 방식을 만드는 것보다 **잘 정리된 웹페이지가 결과적으로 검색엔진에게도 이해하기 좋은 구조가 되는 것**이 더 자연스럽다고 느꼈다.

---

## 처음부터 SEO 기능을 전부 넣지는 않았다

SEO를 알아보다 보면 해야 할 일이 계속 나온다.

고급 메타데이터,

검색엔진별 설정,

구조화된 데이터,

여러 분석 도구처럼 더 깊게 들어갈 수 있다.

하지만 블로그 기능을 너무 많이 넣지 않기로 했던 것과 마찬가지로 SEO도 현재 필요한 범위부터 정리하기로 했다.

우선은

```text
title
description
기본적인 문서 제목 구조
이미지 설명
일관된 URL
OG 정보와의 연결
```

정도였다.

이것만으로도 블로그의 기본 정보를 이전보다 훨씬 명확하게 만들 수 있었다.

필요성이 생기면 이후에 더 확장하면 된다.

---

## SEO를 설정하면서 오히려 웹페이지의 기본을 다시 보게 됐다

처음에는 SEO라는 말을 들으면 검색 결과에서 더 위에 나오기 위한 기술부터 떠올렸다.

하지만 기본 설정을 하나씩 살펴보니 상당수는 검색엔진만을 위한 기능이 아니었다.

페이지마다 제대로 된 제목을 붙인다.

페이지 내용을 짧게 설명한다.

소제목 구조를 정리한다.

이미지가 무엇인지 설명한다.

URL을 함부로 바꾸지 않는다.

이런 것들은 검색엔진이 없어도 웹사이트를 이해하고 관리하는 데 도움이 되는 기준이었다.

그래서 이번 작업을 하면서 SEO를 조금 다르게 보게 됐다.

**검색엔진을 속이거나 특별한 기술로 노출을 만드는 것보다, 먼저 페이지가 자신의 내용을 제대로 설명할 수 있게 만드는 것.**

내 블로그에서 시작한 기본 SEO는 그 정도면 충분했다.

`title`과 `description`은 화면에서 크게 눈에 띄는 기능은 아니다.

하지만 브라우저 탭, 검색 결과, 링크 공유처럼 블로그 밖에서 페이지가 보이는 여러 상황의 기본이 된다.

결국 이번에도 큰 기능을 하나 추가한 것보다 **웹페이지가 무엇인지 제대로 설명하는 작은 정보를 채워 넣은 작업**에 가까웠다.
