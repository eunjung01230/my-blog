프로젝트 화면을 만들다 보면 Figma나 CSS만으로 해결되지 않는 부분이 생긴다.

예를 들면 이런 것들이다.

```text
서비스 로고

앱 아이콘

파비콘

Empty State 일러스트

프로젝트 소개 이미지

OG 이미지에 사용할 그래픽
```

처음에는 이런 이미지가 필요하면 직접 찾아야 한다고 생각했다.

무료 아이콘 사이트를 찾거나,

이미지 사이트를 돌아다니거나,

Figma에서 도형을 직접 조합하는 식이었다.

그런데 AI 이미지 생성 기능을 사용하기 시작하면서 선택지가 하나 더 생겼다.

```text
필요한 이미지 설명
↓
ChatGPT 이미지 생성
↓
결과 확인
↓
수정
↓
프로젝트에 사용
```

현재 ChatGPT에서는 새 이미지를 생성하는 것뿐 아니라 기존 이미지를 업로드해서 수정하고, 특정 영역만 선택해 편집하거나 투명 배경과 원하는 화면 비율을 요청하는 것도 가능하다. 2026년 9월에는 ChatGPT Images 2.5가 적용되면서 이미지 생성과 편집 기능도 계속 개선되고 있다.

처음에는

```text
원하는 아이콘 만들어줘.
```

라고 하면 바로 사용할 수 있는 완성품이 나올 것이라고 생각했다.

하지만 실제로 프로젝트에 사용할 이미지를 만들면서 알게 됐다.

> **이미지를 생성하는 것과 서비스에 사용할 디자인 자산을 만드는 것은 조금 다른 문제였다.**

이번 글에서는 ChatGPT를 이용해 이미지와 아이콘을 만들면서 알게 된 점을 정리해보려고 한다.

---

## 처음에는 그냥 "로고 만들어줘"라고 했다

AI 이미지 생성은 사용법 자체는 어렵지 않다.

원하는 것을 설명하면 된다.

예를 들어

```text
카페 서비스 로고 만들어줘.
```

라고 요청할 수 있다.

그러면 실제로 로고처럼 보이는 결과가 나온다.

문제는

```text
카페 서비스
```

라는 정보만으로는 결정해야 할 것이 너무 많다는 것이다.

AI 입장에서는

```text
어떤 카페 서비스인지?

어떤 사용자를 위한 것인지?

귀여운 분위기인지?

고급스러운 분위기인지?

텍스트 로고인지?

심볼 로고인지?

어떤 색상을 사용할지?
```

모른다.

결국 대부분을 AI가 판단한다.

그러면 결과가 예뻐도

```text
내 서비스 같은 느낌
```

이 아니라

```text
어딘가 있을 것 같은 카페 브랜드
```

가 될 수 있다.

---

## 먼저 이미지의 역할부터 정하는 것이 좋았다

아이콘이나 이미지를 만들기 전에

```text
무엇을 만들 것인가?
```

보다

```text
어디에 사용할 것인가?
```

를 먼저 정하면 훨씬 쉬웠다.

예를 들어 같은 서비스라도 필요한 이미지가 다르다.

### 앱 아이콘

```text
작은 크기에서도 알아볼 수 있어야 함

형태가 단순해야 함

글자가 없어도 의미가 보여야 함
```

### 웹사이트 로고

```text
서비스 이름과 함께 사용할 수 있음

가로형 구성도 가능

브랜드 분위기를 보여줄 수 있음
```

### 파비콘

```text
아주 작은 크기로 표시됨

복잡한 그림은 거의 보이지 않음

심볼 하나가 중요
```

### Empty State 이미지

```text
화면의 의미를 보조

너무 강하게 시선을 빼앗으면 안 됨

본문 UI와 어울려야 함
```

같은

```text
서비스 이미지
```

라도 목적이 다르다.

그래서 나는 이미지를 요청할 때

```text
무엇을 그릴지
```

뿐 아니라

```text
어디에서 사용할지
```

까지 알려주는 것이 중요하다고 느꼈다.

---

## 예를 들어 앱 아이콘을 만든다면

단순히

```text
커피 앱 아이콘 만들어줘.
```

보다 이렇게 설명할 수 있다.

```text
모바일 카페 혜택 관리 서비스의 앱 아이콘을 만들어줘.

커피를 직접적으로 크게 그리기보다
컵과 혜택을 연상할 수 있는 단순한 심볼을 사용해줘.

작은 앱 아이콘에서도 형태를 알아볼 수 있도록
요소를 많이 넣지 말아줘.

텍스트는 넣지 않고,
단순하고 평면적인 형태로 만들어줘.
```

이렇게 요청하면 중요한 조건이 생긴다.

```text
모바일 앱 아이콘

단순함

작은 크기

텍스트 없음

평면적인 형태
```

AI가 결정해야 할 범위가 줄어든다.

---

## 이미지 프롬프트도 길다고 좋은 것은 아니었다

AI 프롬프트라고 하면 굉장히 길게 작성해야 할 것 같았다.

하지만 이미지 생성에서는 중요한 조건을 명확하게 말하는 것이 더 중요했다.

[OpenAI의 이미지 생성 가이드](https://openai.com/academy/image-generation/)에서도 좋은 이미지 프롬프트가 반드시 길 필요는 없으며, 이미지의 **목적·주요 대상·상황·원하는 시각적 스타일과 중요한 제약**을 명확하게 전달하는 것이 중요하다고 설명한다.

그래서 나는 이미지 프롬프트를 대략 이렇게 나눠서 생각한다.

```text
1. 용도

2. 핵심 대상

3. 분위기

4. 색상

5. 형태

6. 제외할 요소
```

예를 들면

```text
[용도]
개발 블로그의 파비콘

[대상]
단순한 노트 또는 코드 기록을 연상시키는 심볼

[분위기]
차분하고 심플함

[색상]
검정과 흰색 중심

[형태]
작은 원형 안에서도 알아볼 수 있는 단순한 형태

[제외]
글자, 복잡한 배경, 3D 효과, 세밀한 장식
```

처럼 정리할 수 있다.

---

## "하지 말아야 할 것"도 중요했다

AI에게 이미지를 만들게 하면 자꾸 무언가를 더하려는 경우가 있다.

```text
그림자

빛 효과

배경 패턴

작은 장식

글자

추가 아이콘
```

이미지를 크게 봤을 때는 멋있다.

하지만 실제 서비스 아이콘으로 사용하면 오히려 복잡해진다.

그래서

```text
단순하게 만들어줘.
```

만 쓰기보다 구체적으로 제한한다.

```text
글자는 넣지 않는다.

그림자는 사용하지 않는다.

배경 패턴을 넣지 않는다.

아이콘 내부 요소는 2~3개 이하로 제한한다.

3D가 아니라 평면적인 그래픽으로 만든다.
```

AI에게

```text
무엇을 추가할지
```

만 알려주는 것보다

```text
무엇을 추가하지 말지
```

도 알려주는 방식이다.

---

## 첫 번째 결과를 바로 쓰지 않았다

이미지를 생성하면 첫 결과부터 꽤 괜찮게 나올 때가 있다.

그러면 바로 프로젝트에 넣고 싶어진다.

하지만 실제 서비스에 적용해보면 문제가 보인다.

```text
작게 보니까 복잡하다.

색상이 UI와 맞지 않는다.

아이콘 테두리가 너무 얇다.

배경색과 구분되지 않는다.

다른 아이콘들과 스타일이 다르다.
```

그래서 첫 번째 생성 결과는

```text
완성본
```

보다는

```text
방향 확인용 시안
```

으로 보는 편이 좋았다.

---

## 생성 → 확인 → 수정의 반복

내가 실제로 사용하기 편했던 방식은 이런 흐름이었다.

```text
첫 이미지 생성
↓
방향 확인
↓
마음에 드는 부분 선택
↓
복잡한 부분 제거
↓
색상 수정
↓
비율 수정
↓
실제 UI에서 확인
↓
다시 수정
```

예를 들어 첫 결과를 보고

```text
전체 형태는 마음에 든다.

하지만 색상은 마음에 들지 않는다.
```

면 처음부터 다시 만들지 않는다.

```text
현재 심볼의 형태는 그대로 유지하고
색상만 브라운 계열로 변경해줘.

새로운 요소는 추가하지 마.
```

처럼 요청한다.

---

## 수정할 때 유지할 것도 말해야 했다

AI에게

```text
색상 바꿔줘.
```

라고 했는데

색상뿐 아니라 형태까지 조금 달라지는 경우가 생길 수 있다.

그래서 수정 프롬프트에서는

```text
바꿀 것

+

유지할 것
```

을 같이 말하는 것이 좋았다.

예를 들어

```text
현재 심볼의 형태와 비율은 그대로 유지해줘.

색상만 수정한다.

초록색은 제거하고
브라운과 크림색 계열로 바꿔줘.

새로운 도형이나 장식은 추가하지 마.
```

처럼 말한다.

---

## 작은 수정은 전체 재생성보다 편집이 좋았다

현재 ChatGPT 이미지에서는 기존 이미지를 다시 올려서 수정하거나, 이미지의 특정 부분을 선택한 뒤 그 영역에 대한 변경을 요청할 수 있다. 선택 영역을 사용하지 않고 대화에서 수정 내용을 설명하는 것도 가능하다.

예를 들어 아이콘은 마음에 드는데

```text
컵 안쪽에 있는 작은 별만 없애고 싶다.
```

고 하자.

전체 이미지를 새로 생성하면 다른 부분까지 달라질 수 있다.

이럴 때는 해당 영역만 선택해서

```text
선택한 작은 별만 제거해줘.
다른 심볼과 색상은 유지해줘.
```

라고 요청하는 편이 낫다.

이 방식은 디자인 AI에서 특정 영역만 수정하는 것과 비슷했다.

---

## 배경이 없는 이미지가 필요할 때

웹이나 앱에 이미지를 넣다 보면 배경이 없는 이미지가 필요한 경우가 많다.

예를 들어

```text
로고

서비스 심볼

일러스트

장식용 그래픽
```

등이다.

흰 배경까지 이미지에 포함되어 있으면 다크모드나 다른 색상의 배경 위에 올렸을 때 사각형이 그대로 보일 수 있다.

그래서 처음부터

```text
배경을 투명하게 만들어줘.
```

라고 요청하는 것이 좋다.

현재 ChatGPT Images는 이미지 생성 지시에서 투명 배경을 요청할 수 있다.

특히

```text
Figma에서 배치

웹에 삽입

앱 아이콘 작업

OG 이미지 조합
```

처럼 다른 디자인 위에 올려야 하는 자산이라면 투명 배경이 편하다.

---

## 하지만 투명 배경이라고 모든 문제가 해결되는 것은 아니다

배경이 투명해도 이미지 가장자리가

```text
흰색 테두리

그림자

Glow 효과
```

를 가지고 있으면 다른 배경에 올렸을 때 어색할 수 있다.

그래서 실제로 사용할 목적이라면

```text
투명 배경

그림자 없음

외곽 Glow 없음

깨끗한 가장자리
```

까지 요청하는 편이 좋았다.

---

## 비율도 처음부터 정해두는 것이 편했다

이미지를 만들고 나서

```text
이거 정사각형이어야 했는데...
```

가 되는 경우가 있다.

특히 사용처마다 필요한 비율이 다르다.

```text
앱 아이콘
→ 1:1

파비콘 원본
→ 1:1

배너
→ 가로형

OG 이미지
→ 공유 카드에 맞는 가로형

프로젝트 소개 이미지
→ 사용하는 레이아웃에 따라 다름
```

현재 ChatGPT 이미지에서는 원하는 화면 비율을 선택하거나 프롬프트에 비율을 포함해서 생성할 수 있다.

그래서 처음부터

```text
1:1 정사각형으로 만들어줘.
```

처럼 사용 목적에 맞는 비율을 알려준다.

---

## 아이콘은 크게 보고 판단하면 안 됐다

아이콘을 생성하면 결과 화면에서는 크게 보인다.

그 상태에서는 세밀한 장식도 예뻐 보인다.

문제는 실제 사용 환경이다.

파비콘이라면 화면에서 정말 작다.

앱 아이콘 역시 홈 화면에서는 생성 결과보다 훨씬 작게 보인다.

그래서 아이콘을 만들 때는 반드시 축소해서 확인해야 했다.

```text
생성 이미지
↓
128px 확인
↓
64px 확인
↓
32px 확인
↓
16px도 확인
```

특히 파비콘이라면 작은 크기에서

```text
무엇인지 알아볼 수 있는가?
```

가 중요하다.

---

## 작게 만들수록 디테일을 빼야 했다

예를 들어 원본 이미지에

```text
커피 컵

쿠폰

별

작은 동전

체크 표시

서비스 이름
```

까지 전부 들어있다고 해보자.

큰 이미지에서는 서비스의 의미가 잘 보인다.

하지만 32px로 줄이면

```text
뭔지 모르는 작은 덩어리
```

가 될 가능성이 높다.

그래서 아이콘에서는 오히려

```text
컵 + 체크
```

또는

```text
하나의 단순한 심볼
```

정도만 남기는 것이 더 나을 수 있다.

---

## 로고와 앱 아이콘도 같은 이미지일 필요는 없었다

처음에는

```text
서비스 로고 하나 만들면
전부 거기에 쓰면 되지 않나?
```

라고 생각했다.

하지만 사용처가 다르다.

예를 들어 서비스 로고가

```text
[심볼] CupPick
```

처럼 되어 있다면 웹 헤더에서는 잘 어울린다.

하지만 앱 아이콘에 그대로 넣으면

```text
CupPick
```

이라는 글자가 너무 작아질 수 있다.

그래서

```text
로고
→ 심볼 + 이름

앱 아이콘
→ 심볼만

파비콘
→ 더 단순화한 심볼
```

처럼 나눌 수 있다.

---

## 하나의 원본에서 파생시키는 방법

완전히 다른 이미지를 각각 만드는 것보다 먼저 핵심 심볼을 하나 만든다.

```text
기본 심볼
```

이 정해지면

```text
기본 심볼
│
├─ 로고
├─ 앱 아이콘
├─ 파비콘
├─ OG 이미지
└─ 프로젝트 소개 이미지
```

처럼 확장할 수 있다.

이 방법을 사용하면 프로젝트 전체의 이미지가 서로 다른 서비스처럼 보이는 문제도 줄일 수 있다.

---

## "같은 스타일로 만들어줘"만으로는 부족할 수 있다

이미 앱 아이콘 하나를 만들었다고 하자.

그다음 Empty State 일러스트를 요청하면서

```text
이거랑 같은 스타일로 만들어줘.
```

라고 할 수 있다.

하지만 내가 생각하는

```text
같은 스타일
```

과 AI가 판단하는 기준이 다를 수 있다.

그래서 어떤 것을 유지할지 구체적으로 설명한다.

```text
첨부한 앱 아이콘과 같은 시각적 방향으로 만들어줘.

- 같은 브라운 계열
- 평면적인 형태
- 굵기가 일정한 선
- 그림자 없음
- 둥근 형태

다만 앱 아이콘 자체를 반복해서 사용하지는 마.
```

처럼 말한다.

---

## 참고 이미지를 함께 사용하는 것도 좋았다

말로만 원하는 이미지를 설명하기 어려울 때가 있다.

```text
이런 느낌인데...
```

라는 순간이다.

이럴 때 참고 이미지를 함께 보여줄 수 있다.

현재 ChatGPT Images는 기존 이미지를 업로드하고 원하는 변경 내용을 설명하는 방식의 편집도 지원한다.

예를 들어 내가 Figma에서 대충 만든 심볼이 있다면

```text
이 구도를 유지하고
선과 형태를 더 정리해서
완성도 높은 아이콘으로 만들어줘.
```

처럼 사용할 수 있다.

---

## 레퍼런스를 줘도 무엇을 참고할지 말한다

앞에서 디자인 레퍼런스를 공부할 때와 같다.

참고 이미지를 하나 주고

```text
이렇게 만들어줘.
```

라고만 하지 않는다.

대신

```text
이 이미지에서
단순한 형태와 선 굵기만 참고해줘.

색상과 심볼 구조는 따라 하지 말아줘.
```

처럼 범위를 정한다.

다른 서비스의 로고나 아이콘을 그대로 복사하는 방향이 아니라

```text
시각적 원리
```

를 참고하는 것이다.

---

## 아이콘에 글자를 넣는 것은 특히 조심했다

이미지 생성 AI는 이미지 내부의 텍스트 표현도 계속 좋아지고 있다. 현재 ChatGPT Images 역시 이미지에 텍스트를 포함하는 요청을 지원한다.

하지만 로고나 앱 아이콘에서는 애초에 글자가 필요한지부터 생각하는 것이 좋았다.

특히 작은 크기에서는

```text
서비스 이름

문구

긴 글자
```

가 잘 보이지 않는다.

그래서

```text
앱 아이콘
→ 가능하면 글자 없이 심볼

로고
→ 필요하면 이름 추가

OG 이미지
→ 텍스트 활용 가능
```

처럼 용도를 나누는 것이 좋았다.

---

## 중요한 텍스트는 코드나 Figma에서 넣는 방법도 있다

예를 들어 AI에게 OG 이미지 전체를 만들게 했는데

```text
MY-BLOG
개발 공부를 기록합니다
```

같은 글자가 들어간다고 하자.

AI가 잘 만들어줄 수도 있다.

하지만 나중에 문구를 바꾸고 싶으면 이미지를 다시 수정해야 한다.

그래서 이런 방법도 있다.

```text
ChatGPT
→ 배경 그래픽 생성

Figma
→ 텍스트 추가
```

또는 웹에서 자동으로 OG 이미지를 만든다면 텍스트를 코드로 넣을 수도 있다.

즉 AI 이미지가 모든 것을 한 장에 완성해야 하는 것은 아니다.

---

## ChatGPT와 Figma를 같이 쓰는 방법

실제로는 둘 중 하나만 사용할 필요가 없다.

예를 들어

```text
ChatGPT
↓
기본 심볼 생성
↓
투명 배경 이미지
↓
Figma
↓
크기·위치 조정
↓
텍스트와 결합
↓
최종 로고
```

처럼 사용할 수 있다.

반대로 Figma에서 먼저 대략적인 구도를 만든 뒤

```text
Figma 초안
↓
ChatGPT
↓
이미지 스타일 정리
↓
다시 Figma
```

로 돌아갈 수도 있다.

각 도구가 잘하는 부분을 나누는 것이다.

---

## 이미지 생성과 UI 디자인을 구분해야 했다

ChatGPT가 이미지를 잘 만든다고 해서 화면 전체를 이미지로 만들어 사용하는 것은 다른 문제다.

예를 들어

```text
로그인 화면을 이미지로 만들어줘.
```

라고 요청하면 정말 멋진 로그인 화면 그림이 만들어질 수 있다.

하지만 그것은

```text
UI 이미지
```

이지

```text
실제 로그인 UI
```

가 아니다.

따라서

```text
버튼

입력창

텍스트

카드

Navigation
```

같은 실제 인터페이스 요소는 Figma나 코드로 만든다.

ChatGPT 이미지는

```text
로고

아이콘

일러스트

배경 그래픽

콘텐츠 이미지
```

처럼 실제 이미지가 필요한 부분에 사용하는 것이 자연스러웠다.

---

## UI 아이콘도 전부 AI로 만들 필요는 없었다

서비스에는 작은 아이콘이 많이 들어간다.

```text
홈

검색

설정

프로필

지도

뒤로가기
```

이런 아이콘까지 하나씩 AI로 생성할 수 있다.

하지만 굳이 그럴 필요가 없는 경우가 많다.

이미

```text
Lucide

Material Symbols

Heroicons
```

같이 일관된 아이콘 라이브러리가 존재하기 때문이다.

일반 UI 아이콘은 라이브러리를 사용하는 편이 더 관리하기 쉬울 수 있다.

AI 이미지 생성이 더 유용한 것은

```text
서비스 전용 심볼

브랜드 로고

앱 아이콘

특수한 일러스트
```

처럼 기존 라이브러리에 없는 이미지다.

---

## 일반 아이콘과 브랜드 이미지를 나누게 됐다

내 기준에서는 이렇게 구분할 수 있었다.

### 아이콘 라이브러리 사용

```text
검색

홈

설정

프로필

뒤로가기

닫기

메뉴
```

### 직접 제작 또는 AI 생성 고려

```text
서비스 심볼

브랜드 로고

앱 아이콘

파비콘

서비스 전용 그래픽

Empty State 일러스트
```

이렇게 나누면 디자인 스타일을 관리하기도 편하다.

---

## 이미지가 예쁘다고 바로 사용할 수 있는 것은 아니었다

AI 이미지 생성 결과를 실제 프로젝트에 넣기 전에 확인할 것이 있다.

```text
파일 형식

배경

이미지 크기

비율

파일 용량

작은 크기에서의 가독성
```

예를 들어 정말 예쁜 앱 아이콘을 만들었는데

```text
3MB
```

라고 하자.

웹에서 작은 아이콘 하나로 사용할 이미지라면 지나치게 클 수 있다.

그래서 생성 이후에도 후처리가 필요할 수 있다.

## 생성 → 최적화 과정

실제 프로젝트에서는 이런 흐름으로 생각했다.

```text
ChatGPT 이미지 생성
↓
최종 디자인 선택
↓
필요한 크기로 조정
↓
배경 확인
↓
파일 용량 확인
↓
필요하면 압축
↓
필요하면 형식 변환
↓
실제 프로젝트 적용
```

앞서 [Figma Export — 디자인을 실제 개발에 가져오는 방법]({{ site.baseurl }}{% post_url 2026-09-25-figma-export-design-to-development %})에서 다뤘던 내용과 다시 연결된다.

이미지를 만드는 것과

```text
웹에서 사용할 수 있도록 준비하는 것
```

은 별개의 과정이다.

---

## PNG와 WebP를 구분해서 생각하기

투명 배경 이미지를 생성했다면 PNG 형태로 다루게 되는 경우가 많다.

하지만 웹에서 사진이나 큰 일러스트를 사용할 때는 파일 용량을 줄이기 위해 WebP 같은 형식으로 변환할 수도 있다.

반대로

```text
SVG가 필요한 아이콘
```

이라면 AI가 생성한 일반 Raster 이미지를 그대로 SVG처럼 사용할 수는 없다.

AI로 만든 아이콘을 Vector 형태로 사용할 필요가 있다면 별도의 벡터화나 Figma에서의 재작업이 필요할 수 있다.

즉,

```text
AI가 아이콘 그림 생성
=
바로 SVG Asset 완성
```

이라고 생각하면 안 된다.

---

## 파비콘에서는 더 단순하게 만들었다

파비콘은 특히 까다롭다.

브라우저 탭에서는 정말 작은 크기로 표시된다.

큰 원본에서 예뻐 보이는

```text
작은 장식

텍스트

얇은 선

복잡한 패턴
```

이 거의 보이지 않는다.

그래서 파비콘용으로는

```text
기본 로고
↓
심볼만 남기기
↓
세부 요소 제거
↓
선 굵게
↓
작은 크기로 테스트
```

하는 방식이 필요했다.

이 과정을 거치면

```text
로고와 파비콘은 같은 브랜드지만
완전히 동일한 파일은 아닐 수 있다.
```

는 것도 이해하게 된다.

---

## 여러 시안을 한꺼번에 만드는 것도 유용했다

아이콘을 하나 만들고 계속 고치는 방법도 있지만,

초기에는 여러 방향을 비교하는 것이 더 빠를 수 있다.

예를 들어

```text
같은 서비스 아이콘을
세 가지 방향으로 제안해줘.

1. 컵 중심
2. 혜택/체크 중심
3. 추상적인 심볼 중심

모두 단순한 평면 디자인으로 만들어줘.
```

처럼 요청할 수 있다.

그다음

```text
1안
2안
3안
```

을 보고 방향부터 고른다.

처음부터 하나의 결과를 계속 수정하는 것보다 디자인 방향을 결정하기 편하다.

---

## 하지만 너무 많은 선택지를 만들 필요도 없었다

AI는 여러 결과를 빠르게 만들 수 있다.

그래서

```text
10개 더 만들어줘.

또 10개 만들어줘.
```

를 반복하기 쉽다.

그러다 보면 오히려 선택하기 어려워진다.

그래서 나는

```text
방향 3개 정도 확인
↓
하나 선택
↓
선택한 안을 발전
```

시키는 방식이 더 좋다고 생각한다.

AI 이미지 도구의 장점은 무한히 생성하는 것이 아니라

**비교할 수 있는 시안을 빠르게 얻는 것**에 있다.

---

## 마음에 드는 부분끼리 합칠 수도 있었다

예를 들어 세 개의 시안 중

```text
A
→ 전체 형태가 좋음

B
→ 색상이 좋음

C
→ 심볼 내부 구조가 좋음
```

이라고 하자.

그러면

```text
A안의 전체 형태를 기준으로 유지하고

B안의 브라운 색상 계열을 적용하고

C안처럼 내부 요소는 더 단순하게 만들어줘.
```

라고 요청할 수 있다.

이것도 디자인 레퍼런스를 조합하는 방식과 비슷하다.

---

## AI에게 "어떤 게 제일 좋아?"라고만 하지 않으려고 했다

여러 시안이 나오면 AI에게

```text
뭐가 제일 좋아?
```

라고 묻기 쉽다.

하지만 내가 사용할 서비스의 목적을 기준으로 직접 비교하는 것이 더 중요했다.

예를 들어 앱 아이콘이라면

```text
작게 봐도 알아볼 수 있는가?

서비스와 연결되는가?

기존 서비스와 너무 비슷하지 않은가?

전체 UI 색상과 어울리는가?

단순한가?
```

를 본다.

AI에게 선택까지 넘기는 것이 아니라

AI를 이용해 **선택할 재료를 만든다.**

---

## 이미지에도 디자인 기준이 필요했다

디자인 시스템이라고 하면 보통

```text
Color

Typography

Button

Card
```

만 생각했다.

하지만 프로젝트에서 사용하는 이미지에도 어느 정도 규칙이 필요했다.

예를 들어 일러스트마다

```text
한 화면은 3D

다른 화면은 수채화

또 다른 화면은 Flat Design
```

이면 같은 서비스처럼 보이지 않을 수 있다.

그래서

```text
색상

선 굵기

평면 / 3D

그림자 사용 여부

모서리 형태

디테일 수준
```

정도를 맞출 필요가 있다.

---

## 내가 이미지 생성 전에 정리할 기준

예를 들어 서비스 전체에서 사용할 이미지의 방향을 이렇게 정할 수 있다.

```text
스타일
→ Flat

색상
→ 브라운 / 크림 중심

그림자
→ 사용하지 않음

선
→ 단순하고 일정하게

배경
→ 기본적으로 투명

디테일
→ 최소화

느낌
→ 차분하고 친근함
```

이 기준을 계속 프롬프트에 반영하면 이미지들이 조금 더 일관되게 나온다.

---

## 생성한 이미지를 실제 화면에 올려봐야 했다

아이콘 파일만 따로 보면 괜찮은데

실제 UI 안에 넣으면 이상할 수 있다.

예를 들어

```text
아이콘 단독
→ 예쁨
```

인데

```text
앱 홈 화면
→ 너무 강해서 다른 요소보다 눈에 띔
```

일 수 있다.

그래서 실제 사용 위치에 배치해본다.

```text
이미지 생성
↓
Figma 또는 실제 UI에 배치
↓
크기 확인
↓
주변 요소와 비교
↓
필요하면 수정
```

이미지는 결국 혼자 존재하는 것이 아니라 화면 안에서 사용되기 때문이다.

---

## 모바일과 데스크톱에서도 다르게 보일 수 있다

큰 데스크톱에서 적당해 보였던 이미지가 모바일에서는 너무 클 수 있다.

반대로 작은 아이콘이 큰 화면에서는 존재감이 없을 수도 있다.

그래서 디자인을 적용할 때는

```text
Desktop

Tablet

Mobile
```

환경도 확인한다.

이건 이후 반응형 디자인 글에서도 다시 다루려고 한다.

---

## 이미지 생성도 "한 번에 완벽하게"가 아니었다

AI를 처음 사용할 때는 항상 이런 기대를 하게 되는 것 같다.

```text
정확한 프롬프트
↓
완벽한 결과
```

하지만 실제로는

```text
대략적인 방향
↓
첫 결과
↓
문제 발견
↓
수정
↓
실제 화면 적용
↓
또 문제 발견
↓
수정
```

에 더 가까웠다.

이 과정이 실패라고 생각할 필요는 없었다.

오히려 디자인 도구를 직접 사용할 때도 같은 과정을 거친다.

AI는 이 반복을 더 빠르게 만들어주는 도구였다.

---

## ChatGPT 이미지 생성에서 가장 편했던 부분

내가 특히 유용하다고 느끼는 것은 **대화로 계속 수정할 수 있다는 것**이다.

새로운 이미지를 만들 때마다 모든 조건을 다시 설명하는 것이 아니라

```text
지금 형태는 유지

색상만 변경

배경 제거

요소 하나 삭제

조금 더 단순화
```

처럼 이어서 이야기할 수 있다.

현재 ChatGPT Images도 생성된 결과를 다시 선택해서 편집하거나 대화에서 바로 변경을 요청하는 흐름을 제공한다.

그래서 이미지 생성도 결국 다른 ChatGPT 작업과 비슷해졌다.

```text
요청
↓
결과
↓
피드백
↓
수정
```

이다.

---

## 2026년에는 템플릿으로 시작할 수도 있다

현재 ChatGPT Images에는 포스터나 로고 같은 이미지를 만들 때 사용할 수 있는 **Templates** 기능도 제공된다.

템플릿을 선택한 뒤 용도와 원하는 세부 내용을 입력하고, 필요한 경우 참고 이미지를 추가하는 방식이다.

그래서 완전히 빈 프롬프트에서 시작하기 어렵다면

```text
Template
↓
기본 방향 선택
↓
내 서비스에 맞게 수정
```

하는 방법도 있다.

다만 템플릿을 사용하더라도 결국

```text
내 서비스에 필요한 것이 무엇인지
```

는 내가 결정해야 한다.

---

## 어떤 이미지를 만들어야 할지 모르겠다면 먼저 대화한다

이미지를 만들기 전에 ChatGPT에게 바로 생성부터 시킬 필요도 없다.

예를 들어

```text
내 서비스에 필요한 이미지 종류를 먼저 정리해줘.
아직 이미지는 생성하지 마.
```

라고 할 수 있다.

그러면

```text
로고

앱 아이콘

파비콘

Empty State

OG 이미지
```

같은 목록을 먼저 정리할 수 있다.

그다음 정말 필요한 것만 만든다.

이 방식은 불필요한 이미지 생성을 줄일 수 있다.

---

## 프로젝트 초기에 이미지부터 너무 많이 만들 필요는 없다

디자인 작업을 하다 보면 재미있어서 이미지부터 계속 만들게 된다.

```text
로고

일러스트

캐릭터

배너

아이콘

배경
```

전부 만들고 싶어진다.

하지만 MVP 단계에서는 필요 없는 것도 많다.

서비스 핵심 기능이 아직 바뀌고 있는데 로고 디테일만 계속 수정하고 있다면 순서가 뒤바뀐 것일 수도 있다.

그래서

```text
서비스 구조
↓
핵심 UI
↓
필요한 이미지 확인
↓
이미지 제작
```

순서가 더 효율적일 수 있다.

---

## 내가 AI 이미지를 사용할 때 지키고 싶은 기준

지금까지 정리하면 다음과 같다.

```text
1. 이미지를 만들기 전에 사용처를 정한다.

2. "예쁘게 만들어줘"만 요청하지 않는다.

3. 용도, 스타일, 색상, 형태를 설명한다.

4. 넣지 않을 요소도 명확하게 말한다.

5. 첫 번째 결과를 완성본으로 생각하지 않는다.

6. 수정할 때 변경할 것과 유지할 것을 함께 말한다.

7. 작은 수정은 전체 재생성보다 부분 편집을 활용한다.

8. 필요한 경우 투명 배경을 요청한다.

9. 사용 목적에 맞는 화면 비율을 지정한다.

10. 아이콘은 반드시 작은 크기로 확인한다.

11. 로고, 앱 아이콘, 파비콘을 무조건 같은 파일로 사용하지 않는다.

12. 일반 UI 아이콘은 기존 아이콘 라이브러리를 먼저 검토한다.

13. 서비스 전용 이미지에 AI 생성을 활용한다.

14. 생성 후 파일 크기와 형식을 확인한다.

15. 실제 UI에 배치해서 다시 확인한다.

16. AI가 만든 결과 중 무엇을 사용할지는 내가 결정한다.
```

---

## 이미지 생성에서도 결국 중요한 것은 기준이었다

처음에는

```text
ChatGPT가 그림을 잘 그리는가?
```

가 가장 중요하다고 생각했다.

하지만 실제 프로젝트에서 사용해보니 더 중요한 질문은 따로 있었다.

```text
내가 어떤 이미지를 필요한지 알고 있는가?
```

였다.

기준이 없다면 결과가 나올 때마다

```text
이것도 괜찮은 것 같고

저것도 예쁜 것 같고
```

계속 방향이 바뀐다.

반대로

```text
서비스 분위기

주요 색상

아이콘 스타일

단순화 정도

사용 위치
```

가 정해져 있으면 AI 결과를 판단하기 쉬워진다.

---

## AI가 디자인을 대신한 것이 아니라 제작 방법이 달라졌다

예전에는 내가 직접

```text
Figma에서 도형 그리기

아이콘 검색

색상 변경

이미지 편집
```

을 했다면,

AI를 사용할 때는

```text
방향 결정

↓

AI에게 생성 요청

↓

결과 판단

↓

수정 지시

↓

실제 디자인에 적용
```

하는 일이 늘었다.

즉 직접 손으로 만드는 시간이 줄어드는 대신

```text
무엇을 만들 것인지

어떤 결과를 선택할 것인지
```

를 결정하는 일이 중요해졌다.

## Figma, Claude Design, ChatGPT 이미지의 역할

지금까지 사용한 도구를 정리하면 각각 조금씩 역할이 다르다.

### Figma

```text
화면 설계

정확한 UI 배치

Auto Layout

Component 관리
```

### Claude Design

```text
대화하면서 디자인 탐색

빠른 시안 생성

화면 구조 수정
```

### ChatGPT Images

```text
로고

아이콘

일러스트

배경 그래픽

이미지 편집
```

물론 기능이 서로 겹치는 부분도 있다.

하지만 모든 도구를 같은 목적으로 사용할 필요는 없다.

---

## 마무리

처음 ChatGPT 이미지 생성을 사용할 때는

```text
말만 하면 이미지가 나온다.
```

는 것이 가장 신기했다.

하지만 실제 프로젝트에 이미지를 넣기 시작하니 중요한 것은 생성 자체가 아니었다.

```text
무엇을 만들지 정하고

↓

첫 결과를 확인하고

↓

필요 없는 것을 빼고

↓

서비스 디자인에 맞게 수정하고

↓

실제 화면에서 다시 확인하는 것
```

이 전체 과정이 필요했다.

그래서 지금은 ChatGPT 이미지 생성을

```text
완성된 디자인을 한 번에 만드는 도구
```

라기보다

```text
내가 원하는 시각적 자산을
빠르게 만들고 수정하는 도구
```

라고 생각한다.

특히 개발자가 혼자 프로젝트를 만들 때

전문적인 이미지 작업이 필요한 순간마다 처음부터 디자인 프로그램을 배우거나 적절한 이미지를 검색하지 않아도

```text
아이디어
↓
AI 이미지
↓
수정
↓
실제 프로젝트 Asset
```

으로 빠르게 연결할 수 있다는 점이 큰 장점이었다.

그리고 여기까지 Figma, Figma Make, Claude Design, ChatGPT 이미지까지 여러 AI와 디자인 도구를 사용하다 보니 자연스럽게 다음 질문이 생겼다.

```text
굳이 이렇게 여러 도구를 써야 할까?

ChatGPT 하나로 다 하면 안 되나?

Claude 하나만 사용하면 안 되나?

Gemini는 어디에 사용할까?
```

실제로 AI들의 기능이 점점 겹치고 있기 때문에

단순히

```text
이 AI가 최고다.
```

라는 식으로 나누기는 어려웠다.

나는 오히려 프로젝트를 진행하면서 각 도구를 **어떤 작업에 사용하는 것이 편했는지**를 기준으로 나누게 됐다.
