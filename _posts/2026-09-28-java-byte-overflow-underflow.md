## 문제

```java
byte bnum = 127;
bnum++;
System.out.println(bnum);

// 위 식을 실행했을 때 예상 값은 127 + 1 이기 때문에 128이 나와야 하지만 실제 값은 다르게 나온다.
// 위 내용이 왜 이렇게 되는 지 생각해보고 설명해보자.
```

포함되어야 하는 내용 : byte , bit , overflow , underflow , type casting

## 1. byte란?

Java의 byte는 정수를 저장하는 자료형이며 **8bit(1byte)**를 사용한다.

```text
1 byte = 8 bit
```

bit는 컴퓨터가 데이터를 표현하는 가장 작은 단위로, 하나의 bit에는 0 또는 1이 들어간다.

8bit로 표현할 수 있는 경우의 수는:

```text
2^8 = 256개
```

이다.

Java의 byte는 양수와 음수를 모두 표현해야 하므로 범위가 다음과 같다.

```text
byte 범위
-128 ~ 127
```

즉,

```java
byte bnum = 127;
```

에서 127은 byte가 저장할 수 있는 가장 큰 값이다.

byte가 8bit = 8자리인 건 맞다. 그런데 Java의 byte는 양수와 음수를 모두 표현해야 하기 때문이다.

8bit 전체로 만들 수 있는 경우의 수는:

```text
2^8 = 256개
```

그런데 범위를 계산할 때는 **부호가 있는 정수(signed integer)**이므로 다음처럼 나뉜다.

```text
byte = 8bit

최솟값              최댓값
-128                 127
 ↓                    ↓
-2⁷       ~        2⁷ - 1
```

왜 2⁷이 나오냐면, 쉽게 처음 배울 때는 8bit 중 최상위 1bit가 음수/양수 표현에 관여하고, 나머지 7bit가 값 표현에 사용된다고 생각하면 된다.

그래서:

```text
2⁷ = 128

음수 : -128 ~ -1  → 128개
0과 양수 : 0 ~ 127 → 128개

총 256개 = 2⁸개
```

### 그런데 왜 양수는 128까지가 아니라 127까지?

0도 한 자리를 차지하기 때문이다.

```text
0, 1, 2, 3, ... 127
```

이렇게 세면 이미 128개의 값이다.

따라서 공식은:

```text
n비트 signed 정수의 범위 = -2^(n-1) ~ 2^(n-1)-1
```

8bit라면:

```text
-2⁷ ~ 2⁷-1 = -128 ~ 127
```

다만 정확히는 Java 정수가 2의 보수(two's complement) 방식으로 표현되기 때문에 이렇게 되는 것이고, 단순히 '1bit는 부호만 저장한다'라고 이해하는 것은 입문용 설명이다.

## 2. 그런데 왜 127 + 1이 -128이 될까?

127을 8bit 이진수로 보면:

```text
127 = 01111111
```

여기에 1을 더하면:

```text
  01111111
+        1
----------
  10000000
```

Java의 byte는 2의 보수 방식으로 음수를 표현하기 때문에 10000000은 128이 아니라 **-128**을 의미한다.

따라서:

```text
127
 ↓ +1
-128
```

이 된다.

이처럼 자료형이 표현할 수 있는 최댓값을 넘어가는 현상을 overflow(오버플로)라고 한다.

```text
byte 최대값 127

126 → 127 → -128 → -127 ...
           ↑
       overflow
```

## 3. 반대로 underflow도 있다

최솟값보다 더 작아지는 경우다.

예를 들어:

```java
byte bnum = -128;
bnum--;

System.out.println(bnum);
```

결과는:

```text
127
```

이다.

```text
byte 최소값 -128

-127 → -128 → 127 → 126 ...
              ↑
          underflow
```

즉 쉽게 기억하면:

```text
overflow  = 최대값을 넘어감
underflow = 최소값을 넘어감
```

참고로 Java 정수 연산에서는 이러한 범위 초과를 overflow로 설명하며, 여기서는 최솟값 아래로 내려가는 경우를 이해하기 쉽게 underflow라고 표현했다.

## 4. 그러면 128을 저장하려면?

byte보다 더 큰 범위를 가진 자료형을 사용하면 된다.

```java
int bnum = 127;
bnum++;

System.out.println(bnum);
```

결과:

```text
128
```

int는 32bit이므로 128을 충분히 저장할 수 있다.

## 5. type casting은 무엇인가?

type casting(형변환)은 한 자료형의 값을 다른 자료형으로 변환하는 것이다.

예를 들어:

```java
int num = 128;
byte bnum = (byte) num;

System.out.println(bnum);
```

여기서:

```java
(byte) num
```

이 type casting이다.

int의 128을 강제로 byte로 바꿨지만, byte는 128을 표현할 수 없다.

그래서 결과는:

```text
-128
```

이 된다.

즉, 형변환을 한다고 해서 byte의 저장 범위가 커지는 것은 아니다. 큰 자료형의 값을 작은 자료형으로 변환할 때는 값이 손실되거나 예상과 다른 값이 나올 수 있다.

## 과제에 적는다면

Java의 byte 자료형은 1byte, 즉 8bit를 사용하며 -128 ~ 127의 정수를 표현할 수 있다. bit는 0과 1을 저장하는 가장 작은 데이터 단위이며, 8bit는 총 256개의 상태를 표현할 수 있다. byte의 최댓값인 127에서 1을 증가시키면 128이 되어야 할 것 같지만, 128은 byte의 표현 범위를 벗어난다. 이처럼 자료형의 최댓값을 넘어가는 현상을 overflow라고 하며, 이 경우 값이 최솟값인 -128로 돌아간다. 반대로 -128에서 1을 감소시키면 127이 되는데, 최솟값보다 작아지는 이러한 현상을 underflow라고 한다. 더 큰 값을 정상적으로 저장하려면 int와 같이 더 넓은 범위의 자료형을 사용해야 한다. 또한 **type casting(형변환)**을 이용하여 다른 자료형으로 변환할 수 있지만, 큰 자료형을 byte처럼 작은 자료형으로 변환하면 표현 범위를 벗어난 값의 정보가 손실될 수 있으므로 주의해야 한다.

## 핵심 흐름만 기억하면

byte는 **8bit(1byte)**를 사용하며 저장 범위는 -128 ~ 127이다.

따라서 최댓값 127에서 1을 더하면 저장 범위를 넘어가면서 **overflow(오버플로)**가 발생해 최솟값인 -128로 돌아간다.

반대로 -128에서 1을 빼면 범위를 벗어나 127이 되며 이를 **underflow(언더플로)**라고 한다.

8bit의 2의 보수 표현에서 비트 연산 결과가 그렇게 해석되는 것이고, 학습할 때는 **"범위를 넘으면 반대쪽 끝으로 순환한다"**고 이해하면 쉽다. 또한 큰 자료형을 byte로 **type casting(형변환)**할 때도 byte의 범위를 벗어나면 값이 달라질 수 있으므로 주의해야 한다.

\: byte = 8bit → 2의 7승 -> -128~127 → 127+1은 범위 초과 → overflow → -128이다.

## 번외 — short와 char

Java에서는 short와 char 둘 다 2byte = 16bit

부호를 다루는 방식이 다르기 때문

```text
short → signed   → 음수 + 0 + 양수  : -32768 ───── 0 ───── 32767
char  → unsigned → 0 이상의 값만    :      0 ───────────── 65535
```

공간 크기는 같지만, 자료형에 따라 그 비트를 해석하는 방법이 다르다
